## Getting Started

To use custom data in your plugin, declare a `custom_data` section in your `CANVAS_MANIFEST.json` with a namespace and access level.
The namespace is a unique identifier scoped to your organization (formatted as `organization__name` with a double underscore),
and the access level controls whether the plugin can read only or read and write data. When the first `read_write` plugin is installed
into a namespace, the system automatically initializes a data namespace, prepares tables, and generates `namespace_read_access_key`
and `namespace_read_write_access_key` secrets that control access for other plugins joining the same namespace.

```json
{
  "sdk_version": "0.1.4",
  "plugin_version": "1.0.0",
  "name": "my_plugin",
  "secrets": ["namespace_read_write_access_key"],
  "custom_data": {
    "namespace": "acme_corp__shared_data",
    "access": "read_write"
  }
}
```

### Step by Step

1. `canvas init`
1. When prompted for a name, enter `Hello Custom Data`
1. `cd hello-custom-data/hello_custom_data`
1. Open `CANVAS_MANIFEST.json` in your preferred editor.
1. Create a `custom_data` block: 
   ```json
   "custom_data": {
     "namespace": "my_org__hello_custom_data",
     "access": "read_write" 
   }
   ```
1. Add `namespace_read_write_access_key` to the `secrets` array (the key will be generated by the system for you)
1. Next, create a `models` directory under the root of your plugin hierarchy, sibling to `CANVAS_MANIFEST.json` and `handlers`
1. Create an `__init__` file inside of `models` and open it in your editor. 
1. Declare the following class within the `__init__` file: 
   ```python 
   from canvas_sdk.v1.data import (Note, ModelExtension)
   class CustomNote(Note, ModelExtension):
       """Extends the SDK Note model with CustomAttribute support
          and reverse mappings from CustomModels."""
       pass 
   ```
1. Open `handlers/event_handlers.py` in your editor. Add `from hello_custom_data.models import CustomNote` to the imports
1. In the code, replace uses of `Note` with `CustomNote`. These objects behave the same as normal, but now have new methods:
   2. `set_attribute`
   3. `set_attributes`
   4. `get_attribute`
1. Add the following lines **after** the `note` reference has been initialized in the code
    ```python
    note.set_attribute("tagged_by_plugin", "hello-custom-data")
    log.info(f"Note tagged by: {note.get_attribute('tagged_by_plugin')}")```
1. Install the plugin to your development environment
1. Tail the logs with `canvas logs`
1. Log into Canvas, navigate to a patient chart, and create a new note

In the logs you will see our message: `Note tagged by: hello-custom-data`

What just happened? When you installed the plugin, a new database namespace called `my_org__hello_custom_data`
was created. Within the namespace are tables that hold information owned by, and managed by, the `my_org` plugins. 
Setting the `tagged_by_plugin` attribute on the CustomNote object caused a new database record to be created. 
This record lives within the `my_org__hello_custom_data` namespace and is private to it. The Note object itself
is unmodified, but the CustomNote subclass enables access to this new property.

[CustomAttributes](/sdk/custom-data-custom-attributes) allow you to decorate any and all SDK objects with text, date, timestamp, boolean, decimal, and JSON data.

[CustomModels](/sdk/custom-data-custom-models) and [AttributeHubs](/sdk/custom-data-attribute-hubs) similarly are stored within a namespace and are thus insulated and protected.
