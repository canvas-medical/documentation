Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed issues where permalinks did not show what they linked to:
  - A permalink to a note scrolled to the note but left it collapsed, most often for locked, signed, and booked or reverted appointment notes. The linked note now opens expanded.
  - A permalink to a command opened the note on a note application's tab when the note type [opens that application by default](/sdk/handlers-embedded-applications/#opening-by-default), which hid the linked command. Command permalinks now open on the Note tab.
- Fixed an issue where modals opened by plugins, in Canvas and the patient portal, did not respond to the keyboard. Pressing Escape did not close them, and pressing Tab moved through the page behind the modal instead of the modal itself. Tab now stays inside the open modal, and Escape closes it.

<span class="tag-api">api</span>

- Fixed an issue where FHIR [Claim](/api/claim/) read and search responses listed line items that had been removed from the claim alongside its active charges. Responses now include only active line items.

<span class="tag-sdk">sdk</span>

- Plugins and messages can now [link patients to the after-visit summary](/sdk/patient-portal/#link-to-after-visit-summaries) of their own locked notes at `/app/note/<note id>/aftervisitsummary` in the patient portal, using the note's UUID. The portal has no built-in link to it. The PDF is the same one a clinician prints from the note.
  - Each download is recorded in the audit log.
  - The new [`PATIENT_PORTAL__DOCUMENT_DOWNLOADED`](/sdk/events/#patient-portal-events) event fires on each download. It targets the patient and carries the document type and note id, so a plugin can record that the patient received their summary.
- Plugins can now open a [LaunchModalEffect](/sdk/layout-effect/#blocking-modals) modal that the user has to finish before moving on, such as a consent form to sign, by setting `dismissible=False`. The user can't close it or navigate away from it, and it closes once the plugin marks the step done or the user signs out.
  - Existing modals are unchanged and can still be closed as before.
- Fixed an issue where opening a plugin page from the patient portal menu could send a signed-in patient to the login screen. Signing in again from there could show a "Your account has been locked" message even though the account was not locked. These pages now open for the signed-in patient.
