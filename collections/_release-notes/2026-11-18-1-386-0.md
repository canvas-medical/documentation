Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Fixed an issue where the FHIR Observation create endpoint accepted vitals values the Vitals command couldn't read. It now returns a 422 that describes the expected value: a blood pressure in systolic/diastolic format (for example 122/68), a pulse rhythm of Regular, Irregularly Irregular, or Regularly Irregular, and a number greater than zero for the other vitals.
- The daily job that marks inactive patients' protocols as not applicable now updates only protocols whose status changes, reducing daily database write volume.
- Fixed an issue where approving or denying a refill, or reviewing a document, from a patient's chart could add the command to the wrong patient's note if another patient's report had just been reviewed from the panel. The command now always goes to the correct patient's note.

<span class="tag-sdk">sdk</span>

- The analytics service accepts usage data only from Canvas instances holding its signing key.
- Fixed an issue where Labcorp electronic lab orders were being rejected by Health Gorilla with "Electronic ordering is not supported for the given performer and requester." Labcorp electronic lab orders now go to Labcorp again. Orders that failed during the outage need to be placed again.
- Fixed an issue where a change in Health Gorilla's lab directory search could redirect electronic lab orders to a different lab. Orders now go to the lab's saved Health Gorilla account.
- No user-facing change. Internal CI: home-app PRs get changed-line coverage reports and an 80% gate from diff-cover in place of Codecov.
- Updated the aiohttp library to address a security advisory.
