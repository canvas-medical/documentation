Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Patient updates sent by plugins leave a patient's business line, default location, default provider, external identifiers, and previous names unchanged unless the plugin sends them.

<span class="tag-sdk">sdk</span>

- FHIR [Medication](/api/medication/) text search (`_text`) now matches regardless of unit spacing: "500mg" and "500 mg" return the same medications, including decimal strengths such as "0.5mg". A glued strength can also return neighboring strengths ("5mg" includes "25 mg").
- Hardened how single sign-on matches an identity provider login to a Canvas account. Canvas support signs in to the shared support account on each instance only through Canvas's Okta single sign-on with a second factor, and every action taken in such a session records which person it was. Opening the Canvas admin while signed out shows the Canvas support sign-in page, with a link to the normal Canvas sign-in.
- Lower CPU overhead on instances with N+1 query monitoring enabled.
- Changes saved through the settings API, such as resetting your calendar's provider and location configuration, now take effect right away instead of the old value continuing to show.
- On instances with ID.me identity verification enabled, the Identity verification item now always appears in the provider menu, even when a plugin limits which menu items are shown. Prescribers can keep verifying through ID.me for Surescripts enrollment. The item stays hidden on instances where ID.me isn't available.
- Canvas Studio can now create, read back, and clean up FHIR test records (patients, observations, tasks, immunizations, questionnaire responses, and lab reports) on an instance during UAT.
- Plugins priced per unit can record each unit with the new RecordUsage SDK effect. Usage & Billing in Canvas Platform lists what Canvas plugins' recorded units come to this month, on a Plugin usage tab beside Tokens.
- The + button on the chart summary's Conditions section adds an Assess command. Commands linked to a deleted Diagnose can be deleted again.
- Admins can now assign the new "Denied access to the admin" permission to a group or a user to block them from Settings (the admin) and plugin logs, while all their other access in Canvas stays the same. Nothing changes until the permission is assigned, and superusers are never blocked.
- No change for customers: model and object permissions are always enforced, as they already are on every instance. The settings that could turn them off are removed.
- When a fax integration key is promoted from one Canvas instance to another, it can now be safely removed from the original instance so faxes stop going to the old one. The key is only removed if it hasn't changed since it was moved.
- Platform promotions can now move a provisioned integration key, such as the faxing API key, from one instance to another. Each transfer is audited on the source instance, and the key's value is kept out of logs and error reports.
- Instances can now allow approved external sites to embed Canvas in an iframe without fully enforcing their Content Security Policy. This is turned on per instance by configuration.
- Fixed an issue where creating or updating a patient through the FHIR API could remove tribal affiliations recorded on other patients.
- Fixed an issue where Labcorp electronic lab orders were rejected by Health Gorilla with "Electronic ordering is not supported for the given performer and requester." Labcorp electronic lab orders now go through successfully. Orders that failed during the outage need to be placed again.
