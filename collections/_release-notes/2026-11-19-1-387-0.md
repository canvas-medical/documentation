Today's release includes the following updates:

<span class="tag-ui">ui</span>

- The Assess command's **Show in problem list** box now sets how the condition is categorized:
  - On: the condition is a problem list item. A new optional **Category Domain** field, such as SDOH or functional status, is filled in from the condition and can be changed.
  - Off: the condition is an encounter diagnosis for this visit only, with no domain.
  - Entering an Assess in error puts back the category and domain it changed.
  - An Assess started before this release and edited afterwards drops the condition's domain when recorded with the box on. Pick the domain again before recording it.
- An optional choice on a command, such as an order's priority, can now be cleared with Backspace or Delete. Referrals and imaging orders save the cleared priority.

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where the fax number filter in Data Integration didn't list every fax line.
  - With a status selected, it lists every line that has faxes in that status, including lines whose faxes have all been processed or junked.
  - With no status selected, it lists every line that has received a fax.
  - A line received both with and without the leading 1 appears once, and selecting it shows all of that line's faxes.
- Fixed an issue where signed-note PDFs, and PDFs attached to Consents created through the FHIR API, downloaded without a `.pdf` extension or file type.
  - New files are stored as PDFs.
  - Files stored earlier are served as PDFs with a `.pdf` filename through FHIR [DocumentReference](/api/documentreference/) and [Consent](/api/consent/) downloads, and through the [DocumentReference](/sdk/data-document-reference/#accessing-document-files) and [PatientAdministrativeDocument](/sdk/data-patient-administrative-document/#accessing-the-document-file) file links plugins read.
- Fixed an issue where an ICD-10 code shared by two conditions on a note appeared twice on its claim. The claim now lists each code once.
- Fixed an issue where typing a full name with a space, such as a staff member's first and last name or a team like "Billing Team", found no one in the assignee pickers on claims, notes, tasks, and reports. The task list's **Team** picker is also wider, so team names no longer get cut off.
- Fixed an issue where a plugin-generated command's **Last modified by** label could name someone who had only printed or faxed the command, or opened its audit history. It now names whoever last changed the command.

<span class="tag-sdk">sdk</span>

- Plugins can now start, edit, and delete [Approve Refill](/sdk/commands/#approverefill) and [Deny Refill](/sdk/commands/#denyrefill) commands in a note, so a refill dashboard plugin can prepare a pharmacy refill response without the provider opening each chart. The provider still reviews and sends every response from the command.
- Fixed an issue where [`BillingLineItem.objects.find()`](/sdk/data-billing-line-item/#filtering) didn't match a value set's CPT and HCPCS Level II codes. eCQM encounter value sets now find their visits.
- The [Anthropic LLM client](/sdk/clients-llms/#anthropic-claude) supports Claude Opus 5.5 and other models that think before answering.
  - A new opt-in `structured_outputs` setting requests structured responses the way these models require.
  - `temperature` is optional, for models that don't accept it.
