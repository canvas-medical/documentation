Today's release includes the following updates:

<span class="tag-ui">ui</span>

- The Assess Condition command now sets each condition's categories, the next step in a gradual update to how Canvas records conditions. Every condition has one main category, such as problem list item or encounter diagnosis, and a problem list item can also have a domain. See [Assessing and Updating Conditions](https://help.canvasmedical.com/articles/7989321964-assessing-and-updating-conditions) in the Canvas Help Center.
  - **Problem list item:** leave **Show in problem list** on. The condition stays on the patient's problem list, and a health concern assessed this way becomes a problem list item.
  - **Category Domain:** a new optional field, available while **Show in problem list** is on, that marks the condition as an SDOH, functional status, disability status, or cognitive status concern. It fills in from the condition and can be changed.
  - **Encounter diagnosis:** turn **Show in problem list** off for a condition that matters only to this visit, such as a sore throat. It has no domain, and the note's plans and billing can still use it.
  - Entering an Assess Condition in error puts back the category and domain it changed.
  - **What's next:** this update is rolling out slowly, over several releases.
    - For now, the Conditions section of the Patient Summary still shows every condition. A future release will use each condition's category to decide what appears there, so the section lists what the care team tracks over time and a one-visit encounter diagnosis stays with its visit.
    - The other commands that record conditions, such as Add Condition and Past Medical History, will follow the same categories.
    - Assess Condition is also replacing Diagnose for new conditions. See [Important Dates](/product-updates/important-dates/).

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where the fax number filter in Data Integration didn't list every fax line.
  - With a status selected, it lists every line that has faxes in that status, including lines whose faxes have all been processed or junked.
  - With no status selected, it lists every line that has received a fax.
  - A line received both with and without the leading 1 appears once, and selecting it shows all of that line's faxes.
- Fixed an issue where signed-note PDFs, and PDFs attached to Consents created through the FHIR API, downloaded without a `.pdf` extension or file type. These documents, including ones saved before this release, now download as PDFs.
- Fixed an issue where an ICD-10 code shared by two conditions on a note appeared twice on its claim. The claim now lists each code once.
- Fixed an issue where typing a full name with a space, such as a staff member's first and last name or a team like "Billing Team", found no one in the assignee pickers on claims, notes, tasks, and reports. The task list's **Team** picker is also wider, so team names no longer get cut off.
- Fixed an issue where a plugin-generated command's **Last modified by** label could name someone who had only printed or faxed the command, or opened its audit history. It now names whoever last changed the command.

<span class="tag-sdk">sdk</span>

- Plugins can now originate, edit, and delete [Approve Refill](/sdk/commands/#approverefill) and [Deny Refill](/sdk/commands/#denyrefill) commands in a note. Plugins can't commit or send them: a staff member still opens the command in the patient's chart to review it and send the response to the pharmacy.
- Fixed an issue where [`BillingLineItem.objects.find()`](/sdk/data-billing-line-item/#filtering) didn't match a value set's CPT and HCPCS Level II codes. eCQM encounter value sets now find their visits.
- The [Anthropic LLM client](/sdk/clients-llms/#anthropic-claude) supports Claude Opus 5.5 and other models that think before answering.
  - A new opt-in `structured_outputs` setting requests structured responses the way these models require.
  - `temperature` is optional, for models that don't accept it.
