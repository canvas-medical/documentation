Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Admin and front-desk staff now have their primary practice location automatically filled in when opening the scheduling modal from a patient's chart, matching the behavior already available to schedulable providers.
- Improved performance of the claims page so it loads faster during normal use.
- Improved performance of the Revenue queue list so it refreshes more efficiently during high-volume claim activity (e.g., batch and clearinghouse/ERA posting), reducing database load and keeping queue claim counts and balances responsive.

<span class="tag-sdk">sdk</span>

- Plugins can now receive Surescripts eligibility responses through the SDK: after an eligibility request is sent, a response event is emitted carrying sanitized plan details (formulary number, payer, group, and coverage IDs) that plugins can use to build follow-up formulary requests.
- Plugin developers can now replace the Schedule Modal with a customized scheduling plugin modal using [Layout Effects](/sdk/layout-effect/).
- Fixed an issue where some chart notes could get stuck loading after a platform update that changed plugin command definitions.
- Internal: the weekly Update FDB workflow now deprovisions ontology databases older than 14 days, preventing stale Aptible Postgres databases from accumulating across environments.
- Plugin developers can now query ReferralReportCoding through the Canvas SDK data module, including ValueSet-based lookups on referral report codings.
- Note state-change plugin pre-create events now run during validation and fire exactly once.
- Internal: the weekly FDB drug-database refresh now streams its medication/NDC mapping instead of materializing whole tables, so it no longer OOM-kills in the 1 GB refresh container. Behavior-preserving — no user-visible change.
