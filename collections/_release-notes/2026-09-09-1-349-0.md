Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- In the revenue queue, filtering the claims list by an insurer that has no payer ID now selects only that insurer. Previously, insurers without a payer ID and similar names were grouped and filtered together.
- Internal: expected HTTP 404 responses are no longer reported to Sentry as errors, cutting a large source of noise. No change to API behavior — 404s are still returned to callers exactly as before.
- The studio-admin-bot service account is now protected in the Django admin console — like root and the Canvas bot, it can no longer be deactivated, deleted, or renamed. This prevents accidental removal of the account and the loss of its admin audit-log history.
- Fixed a timestamp issue with Date/Time of Specimen Collection in [Lab Order](/sdk/commands/#laborder) commands where the am/pm designation and user timezone were not applied correctly.
- Fixed an issue where command editor lookups joined the user table unnecessarily on both command sync and the command origination message. The origination message now names the most recently added editor.

<span class="tag-sdk">sdk</span>

- [Lab Order](/sdk/commands/#laborder) requisition forms now print both Order Date and Time and Collection Date and Time. Previously, Collection Date and Time was the only item shown and was incorrectly printing the Order Date and Time value.
- Canvas resources now carry created and last-modified timestamps, and the read-only replica's SDK data views expose them. Integrations can poll for only the rows that changed since their last run instead of re-reading whole tables, and appointments, patient addresses, and patient contact points support this for the first time.
