Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- In the revenue queue, filtering the claims list by an insurer that has no payer ID now returns only that insurer's claims. Previously every insurer without a payer ID was treated as one, so filtering by any of them returned all of their claims.
- Fixed an issue where Date/Time of Specimen Collection on a [Lab Order](/sdk/commands/#laborder) command did not save the time that was entered. Times saved from this release forward are correct, and the time picker now shows AM/PM.
- [Lab Order](/sdk/commands/#laborder) requisition forms now print Order Date and Time and Collection Date and Time as two separate fields. Previously the form carried only Collection Date and Time and filled it with the time the order was placed, so it never showed when the specimen was actually drawn. The label prints blank when no collection time was recorded.
- Fixed an issue where a note holding commands created through the API or by a plugin could take several seconds to open on instances with many user accounts. Those commands now open without the delay.
- The Canvas Studio service account now carries the same protection in the Canvas admin that root and the Canvas bot already have: it cannot be deactivated, deleted, or renamed. Its admin audit history stays attached to the account.

<span class="tag-sdk">sdk</span>

- The SDK data views now expose `created` and `modified` on nearly every resource, up from about two thirds of them. An integration querying them over the [read-only replica](/guides/audit-logging-and-telemetry/#read-only-replica-database) can select only the rows that changed since its last run instead of re-reading whole tables.
  - Appointments, patient addresses, and patient contact points carry these timestamps for the first time, and are indexed on `modified` so a repeated poll stays fast.
  - The timestamps are columns on the data views. For the newly covered resources, the SDK data models that a plugin reads do not expose `created` and `modified` yet.
- A date answer on a questionnaire is now readable through the SDK data module. [`InterviewQuestionResponse`](/sdk/data-questionnaire/#interviewquestionresponse) exposes `response_option_date` as a real date, so a plugin can filter and compare on it with date lookups such as `__gte` and `__year`.
