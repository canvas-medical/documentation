Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where customer single sign-on could sign in to accounts it should not have matched. Sign-on now checks against a tighter set of accounts.

<span class="tag-sdk">sdk</span>

- Patient portal notifications — new secure messages, lab results, and statements (email and SMS) — now include a magic link that signs the patient straight in and opens the relevant section, with no password step. These links are single-use, and the session they create expires automatically.
- Canvas-generated payment receipts are now exposed read-only through the [data module](/sdk/data/), letting plugins surface a patient's existing receipt PDF (for example, in the patient portal).
- Patient portal plugins can now respond when a patient signs in, whether with credentials, an invite or reset link, or registration. A plugin can open a [modal](/sdk/layout-effect/#modals) on the landing page right after login. Refreshing the page or returning with a remembered session doesn't count as a new sign-in. Portals with no such plugin installed behave as before.
- No user-facing change. Test-only fix for order-dependent primary key collisions in the config schema tests.
- No user-facing change. Built-in content imports that read Google Sheets (lab, imaging, and specialty report templates, questionnaires, trial resources) now fail with the Google API error when a sheet read is throttled or fails, instead of importing nothing.
- Looking up observations by their code is faster, so integrations and plugins that match lab results by code stay fast as data volume grows.
