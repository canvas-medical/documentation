Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Batch patient statements now generate reliably. Statements that cannot be rendered are left out of the batch and counted on the task, and the requester always gets a task saying whether the batch is ready, failed, or had nothing to invoice. A batch that stops partway says how many statements it already created. A second batch request while one is running is turned away. If statement generation stops partway, for example during a PDF service outage, patients it did not reach keep their previous statements.
- Fixed an issue where failed inbound fax retrievals could hang instead of retrying, which blocked new faxes from arriving. They now time out and retry so new faxes keep arriving.
- Fixed an issue where editing a patient's address did not select the saved country and state when they were stored in a different case or spelling. The saved country and state are now selected correctly. Switching the country back to United States now leaves State empty, and International is no longer listed as a state. The address fields for a patient's parent or guardian, and for a coverage's subscriber or guarantor, now work the same way.
- Fixed an issue where an Approve or Deny Refill that cannot be applied, such as one for a refill request that already has a response, was added to the note without warning. It now shows an error and is not added to the note.
- Fixed an issue where an insurance eligibility check failed when a payer left a date blank or sent a benefit amount that isn't a number. The check now completes, and the Eligibility Review shows the payer's benefits.
- Fixed an issue where removing a patient contact who is listed as a participant on a note failed with an error. The contact is now removed from the patient's chart, and existing notes still show them as a participant.
- Fixed an issue in the revamped note where a collapsed Assess hid its nested commands while any of them was uncommitted. A collapsed Assess now keeps its nested commands visible while any of them is uncommitted.
- Fixed an issue where editing a patient address that has no saved country left the country and State field unset. The form now preselects United States and shows the State field right away.

<span class="tag-sdk">sdk</span>

- Internal: Ontologies can now search dose-agnostic medications (for example, "warfarin oral") and run drug-drug and drug-allergy interaction checks on them. This prepares for recording medications without a known dose. Clinicians won't see a change until the follow-up science and home-app work ships.
- The `seed_perf_patient` management command now creates an SDK command for every seeded record, so the seeded chart-import note displays its commands on both note versions.
- A plugin variable set from Canvas Platform now takes effect on the running plugin right away, without redeploying the plugin.
- The [Past Medical History](/sdk/commands/#medicalhistory) command can now record an optional category domain (SDOH, functional, disability, cognitive). It refuses a code already on the patient's chart, pointing to Resolve Condition for an active one and to Assess for a resolved one.
- Canvas REST APIs now answer with JSON only. The HTML API browsing page is no longer served on customer instances or by the shared services. Opening a staff API record in a browser now returns JSON instead of an error page.
- Internal: Preview environments boot an up-to-date, patched kernel and keep running after their host restarts.
- Internal: CI authenticates to AWS with short-lived credentials instead of a long-lived shared key. No change to Canvas behavior.
- Plugin agents can now give a sub-agent or the tool loop a `BaseModelLlmJson` schema its answer must match, and an `Effort` level for how much the model thinks.
- Plugins can now read patient care plans (status, intent, originator, and category coding) through the SDK data module.
- Plugins can now read more clinical data through the SDK data module: consolidated immunizations and their codings, provenance records, lab report producers, lab test ask-at-order-entry answers, note participants, patient known locations, parent or guardian details, and tribal affiliation codings. Note participants whose contact person was deleted stay hidden from plugins.
- Plugins can now read claim history (state, coverage, assignee and snooze changes), claim responses, collection status history, electronic and manual remittances, remittance documents, line item allowed amounts, and remark codes through the SDK data module. Existing payment and posting data now includes a deleted flag, so plugins can leave out deleted records the same way Canvas does.
- Internal: Adds read-only SDK database views for the remaining coding and link tables (e.g. scheduled-together appointments, imaging order assessments, note type durations, DME order action events, diagnostic view elements, command editors). Private Notes editors stay excluded. This lets the companion canvas-plugins release expose them in the plugin data module. No user-visible change until the plugins pin is bumped.
- Internal: Adds database support for document annotations and for documents attached to letters, referrals, and patient charts. Plugin developers can read this data through the SDK data module once the companion canvas-plugins release ships.
- Plugins can now read questionnaire results (scores, abnormal flags, narratives, and codes), questionnaire item groups, interview templates and their questionnaire mappings, interview send events, and interview visual findings through the SDK data module. Columns holding sign-in credentials, such as login links, access tokens, login QR codes, and the email and text message bodies that contain login links, are not available to plugins.
- Plugins can now read population health data through the SDK data module: suspected HCCs, campaigns, interventions, and the patients enrolled in each intervention.
- Internal: Background task workers use less memory at startup, leaving more room for the tasks they run.
