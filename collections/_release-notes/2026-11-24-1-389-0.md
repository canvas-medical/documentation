Today's release includes the following updates:

<span class="tag-ui">ui</span>

- The Past Medical History command now records the condition as a problem list item, continuing the gradual update to how Canvas records conditions. See [Managing Historical Conditions](https://help.canvasmedical.com/articles/3935780129-managing-historical-conditions) in the Canvas Help Center.
  - **Category Domain:** an optional SDOH, functional status, disability status, or cognitive status domain for the problem list item.
  - A condition already on the patient's chart can't be added again. The command points you to Resolve Condition for an active condition, or Assess Condition for a resolved one.

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where batch patient statements could fail to generate. Statements now generate more reliably, and the person who started the batch always gets a task saying whether it's ready, failed, or had nothing to invoice. See [Print Batch Statement](https://help.canvasmedical.com/articles/4083957452-print-batch-statement) in the Canvas Help Center.
- Fixed an issue where new incoming faxes could stop arriving. Incoming faxes now arrive more reliably.
- Fixed issues in the patient address form:
  - The saved country and state are now selected even when they were stored with different capitalization or spelling.
  - An address with no saved country now defaults to United States and shows the State field.
  - The same fixes apply to a patient's parent or guardian address and to a coverage's subscriber or guarantor address.
- Fixed an issue where an insurance eligibility check could fail when a payer left a date blank or sent a benefit amount that isn't a number. The check now completes, and the Eligibility Review shows the payer's benefits.

<span class="tag-api">api</span>

- When a batch of patient statements is generated, the statements it replaces now show as `superseded` in the FHIR [DocumentReference](/api/documentreference/) `status`.

<span class="tag-sdk">sdk</span>

- Plugins can now read much more of Canvas through the SDK data module:
  - [Care plans](/sdk/data-care-plan/), with their category codings.
  - [Claim history](/sdk/data-claim/#claim-history), [claim responses](/sdk/data-claim/#claim-responses), and [remits](/sdk/data-posting/#remits), such as [allowed amounts](/sdk/data-posting/#lineitemallowed) and [remark codes](/sdk/data-posting/#remarkcode).
  - [Questionnaire results](/sdk/data-questionnaire/#questionnaire-results), such as scores and abnormal flags.
  - [Outreach campaigns](/sdk/data-campaign/) with their interventions and enrolled patients.
  - [Document annotations](/sdk/data-document-annotation/) and the documents attached to [letters](/sdk/data-letter/#attached-documents), [referrals](/sdk/data-referral/#attached-documents), and [patient charts](/sdk/data-letter/#patientchartdocument).
  - [Provenance records](/sdk/data-provenance/), [consolidated immunizations](/sdk/data-immunization/#consolidated-immunizations), [lab report producers](/sdk/data-labs/#labreportproducer), [lab test ask-at-order-entry answers](/sdk/data-labs/#ask-at-order-entry-answers), and [note participants](/sdk/data-note/#noteparticipant).
  - More patient details: [collection status history](/sdk/data-patient/#collectionstatushistory), [known locations](/sdk/data-patient/#patientknownlocation), [parents and guardians](/sdk/data-patient/#patientparentguardian), and [tribal affiliations](/sdk/data-patient/#patienttribalaffiliationcoding).
  - More codings and links between existing records, such as [appointments scheduled together](/sdk/data-appointment/#appointmentscheduledtogether), the [assessments on an imaging order](/sdk/data-imaging/#imagingorderassessment), [detected issue mitigations](/sdk/data-detected-issue/#mitigations), the [codes a diagnostic view shows](/sdk/data-diagnostic-view/#the-codes-a-view-shows), [who edited a command](/sdk/data-command/#commandeditedby), the [claims on an invoice](/sdk/data-invoice/#invoiceclaim), [note task labels](/sdk/data-task/#notetasklabel), the [appointment lengths each note type offers when scheduling](/sdk/data-note/#scheduleduration), and the [fax history of a DME order](/sdk/data-fax/#dmeorderactionevent).
- A `POST_COMMAND_ORIGINATE` handler can read the [default values](/sdk/command-metadata-create-form-effect/#default-values) a plugin's form fields declare, which are saved as command metadata when the command is originated.
- A plugin's [Past Medical History](/sdk/commands/#medicalhistory) for a condition already on the patient's chart stays unrecorded in the note instead of recording a duplicate, and plugins can read the chosen domain. `MedicalHistoryCommand` doesn't have a parameter for the domain yet.
