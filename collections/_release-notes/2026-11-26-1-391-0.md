Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Printouts, prescriptions, lab orders, claims, and Surescripts messages now pick a patient's current address. Home addresses, including facility addresses, come before work and temporary ones, the most recently added wins, and an address marked Old is used only when the patient has no other. Chart summary and basic information printouts list each address's use.
- Questionnaire Builder now loads every form instead of stopping at the first 200. More forms load as you scroll the form list, and search covers every form. A newly saved draft opens right away, wherever its name sorts, and can be published from there. Questionnaire Builder is available to every user with the Questionnaire Builder permission.
- Fixed an issue where opening a prospect's EMR from Canvas Platform put the sign-in token in a URL. The token is no longer exposed.
- Fixed an issue on the revamped note where a collapsed Assess with nested commands could truncate its item count. It now shows the item count in full, and a long condition name ends in an ellipsis instead.
- Fixed an issue where searches containing `&` or other special characters did not return matches for the full search text. They now return the expected results.

<span class="tag-sdk">sdk</span>

- Internal: Ontologies can now search dose-agnostic medications (for example, "warfarin oral") and run drug-drug and drug-allergy interaction checks on them. This prepares for recording medications without a known dose. Clinicians won't see a change until the follow-up science and home-app work ships.
- Medication search can now return dose-agnostic results (e.g., "warfarin oral") after the dosed products, so clinicians can record a medication the patient already takes when the dose isn't known. This is opt-in and does not change Prescribe search results.
- No user-facing change. The diagnosis code service can report when each ICD-10 code was retired, for an upcoming change that blocks assessing retired codes.
- The EPCS dashboard no longer shows a Name Mismatch when a prescriber's Surescripts directory name differs only in capitalization, accents, punctuation, or spacing. A failed directory lookup now marks only that prescriber's row.
- Assess Coding Gap's "Accept and Diagnose" is now "Accept and Assess": each picked diagnosis assesses the condition already on the chart, reactivating a resolved one, or records a new one. One "Show in problem list" checkbox and an optional category domain apply to every diagnosis.
- Fixed errors that could occur in the ontologies service right after an upgrade, caused by the service reading responses cached by the previous version.
- A prospect's EMR login on a Canvas sample instance can now prescribe non-controlled medications, sent through Canvas's staging pharmacy service.
- Plugin developers can present a client certificate for mutual TLS through the SDK's [Http](/sdk/effect-http/) client, passing the certificate and key as PEM strings from sensitive plugin variables.
- Plugin developers can now filter SDK integration tasks to electronic lab results, using the new `IntegrationTaskChannel.ELECTRONIC_LAB` channel and `IntegrationTask.objects.electronic_labs()`.
- Plugins can now read Health Gorilla lab account numbers through the SDK data module, so they can see which lab account number each practice location and staff member uses.
- The science service accepts a second service key during a key rotation, so shared keys can be rotated without downtime.
- Shared services accept a second service key during a key rotation, so shared keys can be rotated without interrupting service-to-service calls.
- Deactivating a user now signs them out of every session they already hold and stops the tokens issued to them (service, portal-link-phone, and OAuth tokens) from working.
- Science's condition, history, relation, procedure, and SNOMED search endpoints now require Canvas's service credentials, like the rest of the science service.
- Configuration promotions from Canvas Platform work on every instance connected to Platform, with no per-instance key to set up first.
- The PDF printing service only renders Canvas pages, and pages it renders can no longer load files from the server.
- Developers can add the `Preview-Aptible` label to a pull request to deploy its preview on Aptible, and comment `/wake` to wake a preview that went to sleep.
- Staff using the Django admin on Canvas services are no longer blocked when the admin page loads its own scripts.
- Internal cleanup with no change to how Canvas behaves.
- A promotion from Canvas Platform can create staff members the target instance does not have yet, with their login, language, and roles. Staff the target cannot set up safely are skipped, with the reason shown before the promotion is applied. Plugins that listen for new staff members see a promoted staff member when that record is next edited.
- Canvas services calling the shared pharmacy, science, ontologies, and web-to-pdf services are no longer at risk of being blocked by those services' scanner protection.
- A promotion from Canvas Platform now carries a team's phone and email, such as the billing phone printed on patient statements, and the appointment durations offered for each reason for visit.
- Every instance's security audit trail (sign-ins, staff and permission changes, chart access) now also streams to Canvas's own security monitoring, independent of any SIEM export a customer configures.
