Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where electronic remittances stopped posting automatically for insurers configured with two or more entries in their "Accept remittances from" list. The payment never posted and the claim was left commented "coverage with remit payer id not found in claim", so staff only noticed when a balance looked wrong. Remittances for these insurers now post as expected.
- Imaging result codes are now normalized as results are ingested, so a code carrying stray or doubled spaces no longer makes FHIR `Observation` and `DiagnosticReport` reads and searches fail with a 500 error. The usual source was a template field holding a measurement and its laterality as a comma-separated pair, where the second code kept its leading space. Health Gorilla PDF-report attachments are also skipped on ingest, so they no longer create empty lab values.
- IP allow and deny lists under Network Settings, the sign-in rate limit, the request log, and the `loginIPAddress` reported through the API now all read the same network address for a request — the one Canvas's own load balancers recorded — so the four agree on where a request came from.

<span class="tag-ui">ui</span>

- Moving a batch of claims between queues — **Batch actions → Move claims to queue** on the Revenue worklist — has been reworked end to end. The action used to run behind a browser pop-up that showed no progress and reported no outcome, so a large or failed move looked the same as a successful one.
  - The move itself is much faster, and no longer slows the rest of Canvas down while it runs.
  - A dialog replaces the browser pop-ups, and names how many claims match your current filters — every matching claim, not only the rows shown in the table. When nothing matches, it tells you there is nothing to move.
  - A spinner runs while the claims are counted and again while they are moved, and the dialog can't be dismissed part-way through a move.
  - When more claims match than one run will move, the result says how many are left, so you can repeat the action to work through them.
  - The outcome is reported when the move lands — including when it doesn't finish — and the claim table refreshes as you close the dialog.

<span class="tag-config">config</span>

- Canvas can now keep a security audit trail of sign-ins, chart access, and clinical data changes, and stream it to your own SIEM. The trail is recorded in the OCSF standard, and its events carry opaque identifiers only — never patient or provider names, dates of birth, or clinical values. There are two ways to read it:
  - A retained, read-only audit-trail view inside Canvas, for customers who don't run a SIEM.
  - An export that posts the events to an HTTPS endpoint you nominate, such as a Splunk HEC, a Datadog intake, or a generic webhook.
- The audit trail is off unless it has been turned on for your instance, and its settings sit in a section of the admin only Canvas can reach. Reach out to Canvas support to enable it for your instance and to set:
  - `SECURITY_AUDIT_CAPTURE_ENABLED` — record the trail. On once the capability is enabled; turn it off to stop recording entirely.
  - `AUDIT_RETENTION_DAYS` — how long events stay queryable in Canvas before older ones are archived. Defaults to 90 days.
  - `SIEM_EXPORT_ENABLED` — ship the recorded events on to your SIEM.
  - `SIEM_ENDPOINT_URL`, `SIEM_AUTH_HEADER_NAME` and `SIEM_AUTH_HEADER_VALUE` — where to post the events, and how to authenticate to it.
  - `SIEM_PHI_MODE` — `direct` sends Canvas's own patient and resource identifiers; `pseudonymized` sends a keyed hash of them instead, for keeping PHI scope out of your SIEM.
  - `SIEM_BATCH_MAX` — events per request. Defaults to 500.
  - `SIEM_MAX_ATTEMPTS` — how many times a payload your endpoint rejects is retried before it is set aside. Defaults to 5. An endpoint that is simply unreachable is retried indefinitely and never set aside.
- Admins can now set a new instance-wide Constance config setting, `MAX_BATCH_CLAIM_QUEUE_MOVE`, that caps how many claims one run of **Batch actions → Move claims to queue** will move. Defaults to 2,000; when more claims match your filters, the action reports how many remain and you run it again to move the next batch.

<span class="tag-sdk">sdk</span>

- Seven more [commands](/sdk/commands/) now reject a record that belongs to a patient other than the one whose chart is being written to. The check runs when the command is written, so a plugin is told rather than the record being applied to the wrong chart, and it applies to editing an existing command as well as originating a new one:
  - [Lab Review](/sdk/commands/#labreview), [Imaging Review](/sdk/commands/#imagingreview), [Referral Review](/sdk/commands/#referralreview) and [Uncategorized Document Review](/sdk/commands/#uncategorizeddocumentreview) — the reports named in `report_ids`. One foreign report among several valid ones rejects the whole command.
  - [Resolve Condition](/sdk/commands/#resolve-condition) — `condition_id`.
  - [Stop Medication](/sdk/commands/#stopmedication) — `medication_id`.
  - [Remove Allergy](/sdk/commands/#removeallergy) — `allergy_id`. Its `narrative` also now accepts up to 512 characters.
- Fixed an issue where the [Update Goal](/sdk/commands/#updategoal) command accepted a `goal_id` belonging to any patient in the instance, and then filled the update's due date and priority from that patient's goal. Update Goal now confirms the goal is on the chart being written to, and reports a validation error naming the goal when it isn't — where previously an id that matched nothing was passed over in silence. The parameter's documentation is also corrected: `goal_id` takes the goal's `id`, not its `dbid`.
- The [Questionnaire](/sdk/commands/#questionnaire) command can now be answered by passing an `answers` list, instead of retrieving the questionnaire's questions and branching on each one's type. Each entry names a question and gives its response in the form that question takes — text, a number, the id of a radio option, or one `Selection` per ticked checkbox option, each of which can carry its own comment. A question or option id the questionnaire doesn't define raises an error rather than recording something it has no place for.
- Plugins can now expose Canvas commands as HTTP endpoints. [`CommandAPI`](/sdk/handlers-simple-api-commands/) is a [SimpleAPI](/sdk/handlers-simple-api/) that reads a request body onto a command, validates it against that command, and emits the effects — you declare the routes and who may reach them. It covers originating a command, editing a staged one, and running the command's own actions such as commit or enter-in-error. Passing a `command_id` of your own is refused if that id is already taken, so a retry cannot write the command twice. [Writing Commands Over HTTP](/guides/writing-commands-over-http/) walks through building one, including how to check that the caller may write to the note in question.
