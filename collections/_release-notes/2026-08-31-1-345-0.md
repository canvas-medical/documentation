Today's release includes the following updates:

<span class="tag-ui">ui</span>

- Moving a batch of claims between queues — **Batch actions → Move claims to queue** on the Revenue worklist — has been reworked end to end. The action used to run behind a browser pop-up that showed no progress and reported no outcome, so a large or failed move looked the same as a successful one.
  - Several performance improvements make the move itself considerably faster.
  - A dialog replaces the browser pop-ups, and names how many claims match your current filters — every matching claim, not only the rows shown in the table. When nothing matches, it tells you there is nothing to move.
  - A spinner runs while the claims are counted and again while they are moved, and the dialog can't be dismissed part-way through a move.
  - One run moves up to 2,000 claims by default, which an admin can change with the `MAX_BATCH_CLAIM_QUEUE_MOVE` setting in the config section below. When more than that match, the result says how many are left, so you can repeat the action to work through them.
  - The outcome is reported when the move lands — including when it doesn't finish — and the claim table refreshes as you close the dialog.

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where electronic remittances stopped posting automatically for insurers configured with two or more entries in their "Accept remittances from" list. The payment never posted and the claim was left commented "coverage with remit payer id not found in claim", so staff only noticed when a balance looked wrong. Remittances for these insurers now post as expected.
- Imaging result codes are now normalized as results are ingested, so a code carrying stray or doubled spaces no longer makes FHIR `Observation` and `DiagnosticReport` reads and searches fail with a 500 error.
- Fixed an issue where the rendered report PDF that Health Gorilla delivers alongside a lab's real results created an empty lab value and lab test on the patient's chart. Only the exact name "PDF Report" was recognized as the attachment, so variants such as "Clinical PDF Report" or "Enhanced PDF Report" came through as results. The attachment is now recognized however it is named.

<span class="tag-config">config</span>

- Canvas can now keep a security audit trail of sign-ins, chart access, and clinical data changes, and stream it to your own SIEM. The trail is recorded in the OCSF standard, and its events carry opaque identifiers only — never patient or provider names, dates of birth, or clinical values. It can be read as a retained, read-only view inside Canvas, or exported to an HTTPS endpoint you nominate. Off by default; reach out to Canvas support to enable it for your instance and to set the retention period, the endpoint, and whether identifiers are sent directly or as a keyed hash. [Read more.](https://help.canvasmedical.com/articles/3718661267-security-audit-trail-and-siem-export)
- Admins can now set a new instance-wide Constance config setting, `MAX_BATCH_CLAIM_QUEUE_MOVE`, that caps how many claims one run of **Batch actions → Move claims to queue** will move. The cap is what keeps a very large move performant: instead of one action taking on an unbounded amount of work, a big queue is moved in batches. Defaults to 2,000; when more claims match your filters, the action reports how many remain and you run it again to move the next batch.

<span class="tag-sdk">sdk</span>

- Eight more [commands](/sdk/commands/) now carry additional validation on the record they point at: the id must name a record belonging to the same patient as the `note_uuid` you pass — or, when the command names no note, as the `command_uuid` you pass. A record on any other patient's chart is refused, and the error names the id that failed:
  - [Lab Review](/sdk/commands/#labreview), [Imaging Review](/sdk/commands/#imagingreview), [Referral Review](/sdk/commands/#referralreview) and [Uncategorized Document Review](/sdk/commands/#uncategorizeddocumentreview) — every id in `report_ids` must name a report that is still awaiting review and is on that patient's chart. A single foreign report among otherwise valid ones rejects the whole command.
  - [Resolve Condition](/sdk/commands/#resolve-condition) — `condition_id`.
  - [Stop Medication](/sdk/commands/#stopmedication) — `medication_id`.
  - [Remove Allergy](/sdk/commands/#removeallergy) — `allergy_id`.
  - [Update Goal](/sdk/commands/#updategoal) — `goal_id`. Its documentation is also corrected: the parameter takes the goal's `id`, not its `dbid`.
- Four of those commands also validate the *format* of the id, not only whose it is. `condition_id`, `medication_id`, `allergy_id` and `goal_id` are now typed as ids rather than as free text, so a value that isn't a well-formed id is refused when the command is built instead of when it reaches the chart. The [Remove Allergy](/sdk/commands/#removeallergy) command's `narrative` also now accepts up to 512 characters.
- The [Questionnaire](/sdk/commands/#questionnaire) command can now be answered by passing an `answers` list, instead of retrieving the questionnaire's questions and branching on each one's type. Each entry names a question and gives its response in the form that question takes — text, a number, the id of a radio option, or one `Selection` per ticked checkbox option, each of which can carry its own comment. A question or option id the questionnaire doesn't define raises an error rather than recording something it has no place for.
- Plugins can now expose Canvas commands as HTTP endpoints. [`CommandAPI`](/sdk/handlers-simple-api-commands/) is a [SimpleAPI](/sdk/handlers-simple-api/) that reads a request body onto a command, validates it against that command, and emits the effects — you declare the routes and who may reach them. It covers originating a command, editing a staged one, and running the command's own actions such as commit or enter-in-error. Passing a `command_id` of your own is refused if that id is already taken, so a retry cannot write the command twice. [Writing Commands Over HTTP](/guides/writing-commands-over-http/) walks through building one, including how to check that the caller may write to the note in question.
