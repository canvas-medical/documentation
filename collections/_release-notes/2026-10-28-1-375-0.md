Today's release includes the following updates:

<span class="tag-portal">portal</span>

- Add your own band to the top or bottom of every patient portal page! Show a banner, footer, or toolbar that stays on screen as patients move between pages, with one band on each edge sized to fit your content. See [Portal Docked Applications](/sdk/handlers-embedded-applications/#portal-docked-applications).
- Fixed an issue where the patient portal side menu didn't scroll when the window was too short to show every item. The menu now scrolls, and the Privacy link sits below the last menu item.

<span class="tag-bugfix">bugfix</span>

- Fixed BMI and growth percentiles recorded from [vitals](/sdk/data-vital-sign-reading/):
  - Patients 20 and over get a BMI in kg/m².
  - Patients from age 2 up to 20 get a BMI-for-age percentile, and patients under 2 get a weight-for-length percentile, including from the length recorded in the pediatric physical exam.
  - Each uses the patient's age on the day the vitals were taken and compares against the growth chart for that age.
  - No percentile is recorded when no growth chart applies.
- Fixed an issue where refill renewal requests could land on a deactivated patient chart. When the patient has one other active chart with the same name and date of birth, the renewal now goes to that chart. Otherwise, the request appears in the refill queue as an unrecognized patient so staff can link it. Plugins see the same chart on [`RefillRequest`](/sdk/data-refill-request/).
- Fixed an issue where many automatic insurance eligibility checks failed each morning.
  - Checks now run at a different time for each instance between 5:13 and 7:13 AM local time.
  - A check that fails for a temporary reason is retried once, and the coverage is checked again on the next day's run.
  - Plugins can see which checks failed for a temporary reason with [`EligibilityResponse.valid_request`](/sdk/data-eligibility-response/).
- Improved the Family History relationship lookup. The Relationship field now lists exact matches first, so typing "sister" highlights "Sister" instead of "Half-sister", and [`FamilyHistoryCommand`](/sdk/commands/#familyhistory) saves the exact relationship a plugin sends.
- Fixed an issue where a command a plugin added to a note, right after a staff member added another command, didn't show in the note until the next edit. The command now appears right away.
- Fixed an issue where text typed into a newly added command was lost if it was typed before the command finished saving.
- Fixed an issue where Fax Event History was missing from a note's triple-dot menu. Staff can check a note's fax status from the menu when faxing is set up.
