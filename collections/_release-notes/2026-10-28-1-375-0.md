Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Vitals now record BMI in kg/m² for patients aged 20 and over, BMI-for-age percentiles from age 2 up to age 20, and weight-for-length percentiles under age 2, using the patient's age on the day the vitals were taken. Growth percentiles compare against the curve for the patient's actual age, and no percentile is recorded when no growth chart applies. BMI observations are created for vitals readings recorded from this release onward; earlier readings are not backfilled.
- Fixed an issue where refill renewal requests could land on deactivated patient charts. When a renewal comes in for a chart that has since been deactivated, Canvas now routes it to the active chart for that patient. If there's no active chart — or more than one that matches — the request appears in the refill queue as an unrecognized patient so it can be linked manually.
- Fixed an issue where automatic insurance eligibility checks were rejected by ClaimMD with a 403 because too many Canvas instances ran them at the same time. Checks now run at a different time for each instance between 5:13 and 7:13 AM local time, with a short gap between checks. A check that fails for a technical reason is retried once and is not counted as a recent check, so the coverage is checked again on the next run.
- Fixed an issue where automatic insurance eligibility checks were rejected by ClaimMD with a 403 because too many Canvas instances ran them at the same time. Checks now run at a different time for each instance between 5:13 and 7:13 AM local time, with a short gap between checks. A check that fails for a technical reason is retried once and is not counted as a recent check, so the coverage is checked again on the next run.
- Fixed an issue in the Family History command's Relationship field where typeahead results ranked longer variants above exact matches — typing "sister" auto-highlighted "Half-sister" instead of "Sister". Exact matches now rank first, and Family History commands added by plugins now save the exact relationship sent (e.g. "Sister", not "Half-sister").
- Fixed an issue in the patient portal where the side menu did not scroll when the window was too short to show every item, and the Privacy link covered the last menu item. The menu now scrolls, and the Privacy link sits below the last item.
- Fixed an issue where text typed into a newly added command while it was still being saved for the first time was lost.
- Fixed an issue where a command added to a note by a plugin right after another command was added did not show in the note until the next edit. The command now appears immediately.
- Fixed an issue where notes on the new note layout did not show Fax Event History in the note header's triple-dot menu when faxing was set up. Staff can now check a note's fax status from the menu.

<span class="tag-sdk">sdk</span>

- Hardened how single sign-on matches an identity provider login to a Canvas account. Canvas support signs in to the shared support account on each instance only through Canvas's Okta single sign-on with a second factor, and every action taken in such a session records which person it was. Opening the Canvas admin while signed out shows the Canvas support sign-in page, with a link to the normal Canvas sign-in.
- Plugins can add a band at the top or bottom of every signed-in patient portal page with PortalDockedApplication. The band stays on screen while the patient moves between pages.
- Developer-facing: pushing a new commit to a PR cancels that PR's older Cypress and pre-commit runs, and hung Cypress groups time out after 45 minutes, so CI in other repos no longer waits behind stale monorepo runs.
- Promotions between instances, and credentials entered for an instance from Platform, can now set the Stripe public key and connected account ID, the Claim.MD username, the Sfax username, and the dialing URL template and label on the target instance. Values are entered for each instance and are never copied from the source.
- Developer-only: the home-app test and dev images no longer install line-profiler and no longer need a compiler to build.
- Developer-only: home-app Pytest results arrive about a minute sooner on each push.
- Developer-only: home-app test coverage is measured per line instead of per branch, and Pytest results arrive about a minute sooner.
- Canvas Medical's service accounts can no longer have their email changed or be sent a password reset link from the user admin, except by a Canvas superuser.
- Plugin data access tokens are now accepted only by the Canvas instance that issued them. Plugins are unaffected.
- Developer-only: Cypress CI groups spend less time on setup.
- Developer-only: fixed a flaky end-to-end test for collapsing an uncommitted goal command.
- Stripe payment features are now allowed to reach Stripe's servers under Canvas's Content Security Policy.
- Single sign-on now always requires the identity provider to sign its sign-in response, regardless of an instance's custom SSO settings. Identity providers that sign either the response or the assertion keep working as before.
