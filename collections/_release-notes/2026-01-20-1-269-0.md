Today's release includes the following updates:

<span class="tag-api">api</span>
- Fixes patient consents validation errors when performing Read/Search out of FHIR for consents that were rejected by the patient via the patient portal
- Fixes the FHIR Patient Create endpoint from creating phone numbers with no digits. 
- Fixed a bug where FHIR QuestionnaireResponse incorrectly saved the submitted display name for coding options. Responses now use the display name from the questionnaire stored in the database

<span class="tag-ui">ui</span>
- Updates the “Learn more” link in a Patient’s profile’s care team section. 

<span class="tag-bugfix">bugfix</span>
- Fixes an issue when using a permalink to navigate to a specific note in the patient chart, but removing any applied filters except show future appointments
- Fixed a bug where carry-forward responses from previous questionnaire versions displayed the old version's display names. These responses now use the current questionnaire version's display names
- Fixed a bug where carry-forward responses were incorrectly pulling from the latest created records instead of the latest modified records. 

<span class="tag-config">config</span>
- Add a configuration to be able to turn off sticky filters, please reach out to support if you would like to turn this feature off.
