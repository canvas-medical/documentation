Today’s release includes the following updates:

<span class="tag-sdk">sdk</span>
- Extends appointment data model to support appointment metadata. [Read more.](/sdk/data-appointment/#appointmentmetadata)
- Adds AppointmentMetadata effect for creating and updating custom key-value metadata on appointment records. [Read more.](/sdk/effect-appointment-metadata/)
- Adds support for plugins to define custom form fields when scheduling appointments, stored as appointment metadata. [Read more.](/guides/appointments-additional_fields/)
- Enables developers to embed custom logic into the scheduling form using new `APPOINTMENT__FORM__PROVIDERS__PRE_SEARCH` and `APPOINTMENT__FORM__PROVIDERS__POST_SEARCH` effects. [Read more.](/sdk/events/#appointments)
- Adds support for creating and managing recurring appointments via plugins by introducing the parent_appointment field on the appointment model. [Read more.](/sdk/data-appointment/)
- Adds support for applications to react to context changes within the revenue module via the `on_context_change()` method, providing URL, patient, user, and resource-specific context, allowing apps to update as you navigate through claims. [Read more.](/sdk/handlers-applications/#context-data-structure)
- Adds immunizations to the data module. [Read more.](/sdk/data-immunization/)


<span class="tag-ui">ui</span>
- Removes provider requirement in scheduling form, allowing staff to search for availability across all providers [Read more.](https://help.canvasmedical.com/articles/4617508394-managing-appointments#scheduling-appointments-6) 
- Hides future appointments in chart through a new constance config that sets the default number of days of upcoming appointments shown in the patient timeline

<span class="tag-api">api</span> <span class="tag-breaking-change">breaking change</span>
- Changes the FHIR Task update endpoint default note behavior from note-append to note-replace (phase 1); Developers must send all notes in update requests or update the header to note-append to avoid note loss. Support for the prefer header will be removed on 9/30/25. [Read more.](/product-updates/important-dates/)
