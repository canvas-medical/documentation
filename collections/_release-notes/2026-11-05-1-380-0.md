Today's release includes the following updates:

<span class="tag-sdk">sdk</span>

- Plugins can now customize the subject and body of the patient portal invite and password reset emails. Otherwise, patients get the standard email. See [Customize the Login Email](/sdk/patient-portal/#customize-the-login-email).
- A new util, [`search_slots()`](/sdk/utils/#searching-for-open-appointment-slots), lets plugins search open appointment times with the same search the Canvas booking screens use, filtered by location, provider, visit type, and length. A plugin's own booking screen can offer the same times Canvas does.

<span class="tag-config">config</span>

- As part of [retiring the Diagnose command](/product-updates/important-dates/), a new setting lets your instance record an Assess any time a plugin or a FHIR integration adds a Diagnose. The Assess reuses a condition already on the patient's chart instead of adding a duplicate. To use this before Diagnose is officially retired, reach out to Canvas support.
  - **Plugins:** existing plugins that add a [Diagnose](/sdk/commands/#diagnose) work without changes, and handlers receive Assess events for these commands.
  - **FHIR:** a [Condition create](/api/condition/) for an active condition adds an Assess instead of a Diagnose. A create for an ICD-10 code already charted for the patient is rejected.

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where a plugin could reschedule an appointment after the patient was checked in, leaving the visit's note without its sign buttons. The [reschedule effect](/sdk/effect-notes/#reschedule-appointment) now returns a validation error for a checked-in appointment, and the note stays ready to sign.
- Fixed an issue where a note left open in one tab kept saving changes after it was deleted or canceled in another. Changes to a deleted or canceled note are not saved.
- Canvas, the patient portal, and the login page load faster, with the largest improvement on repeat visits.
