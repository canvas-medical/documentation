Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Fixed an issue where the SDK's `Appointment.reschedule` effect could reschedule an appointment whose patient was already checked in. The effect now raises a validation error, and the visit stays checked in so the provider can sign it.
- Fixed an issue where edits to a note that had been deleted or canceled in another tab were saved to that note. Those edits are now rejected.
- Fixed an issue where plugin usage purge tests did not commit their usage rows or use the single read position, causing inconsistent CI results. The tests now pass consistently.

<span class="tag-sdk">sdk</span>

- Plugins can now customize the subject and body of the patient portal invite and password-reset emails. If no plugin provides custom content, or the plugin's content is invalid or late, the standard email is sent. The login link is always included.
- With the FHIR Condition update enabled, active conditions written through the [FHIR Condition API](/api/condition/) are recorded as an Assess instead of a Diagnose. A FHIR Condition create for an ICD-10 code the patient already has is refused, so repeated writes no longer create duplicates. Entering a FHIR condition in error withdraws the command that recorded it, and is refused once anything else references the condition. FHIR Condition notes over 1,000 characters are refused instead of failing.
- Plugins can now search open appointment times using the same slot search as Canvas's native scheduling screens. Results can be filtered by location, one or more providers, visit type and duration, so a plugin's own booking screen offers the same times Canvas does.
- Internal: django-constance is upgraded from 2.9.1 to 4.3.5, and live settings are stored as JSON instead of pickles. Each instance's settings move to the new storage once, at the first deploy of this release. No user-facing behavior change.
- Developers: a new instance switch records a Diagnose added by a plugin as an Assess, so it reuses a condition already on the patient's chart instead of creating a duplicate. Off by default; existing plugins need no change. With it on, plugins see Assess events and schema_key "assess" for those [commands](/sdk/commands/).
- Internal: Canvas Platform can now read an installed plugin's live state (version, checksum, enabled flag, setting digests, namespace key status) and download its running package through two read-only, Platform-authenticated endpoints, so plugins installed with `canvas install` can be reconciled. Nothing changes on the instance.
- From December 14, 2026, Canvas instances refuse plugin install, configuration, and uninstall made directly with the `canvas` CLI, and point to `canvas deploy` through Canvas Platform. Canvas can set a later date for one instance.
- Fixed an issue where a field you filled in on a command, such as Status on a coding gap, could be cleared if you entered it right after picking a value that reloads the command. Your entries now stay on screen and match what is saved.
- Family members and other representatives given access to a patient's portal chart now have to confirm the patient's date of birth once before they can see the chart. Three wrong tries lock the chart until staff unlock it from the Profile. Representatives can also choose "I don't know this person", which pauses their access and flags the contact so staff can correct it. When staff correct that contact, the access moves to the right person.
- Canvas loads faster on repeat visits: browsers now keep the app's code files cached instead of checking for them again on every page load.
- Lab partner test case scripts add their lab orders to the note through the order's SDK command, so the order appears in the note on both note versions.
- Clients blocked for scanning or probing now wait 10 seconds for each rejected request instead of being answered at once, so one abusive client can no longer exhaust the load balancer's connections and cause errors for everyone else.
- The patient portal now limits how many fields a signed-out request can ask for at once, so a single request can no longer repeat a sign-in or verification step dozens of times. Normal portal use is unaffected.
- Fixed an issue where form-encoded requests sent to the internal service proxy routes returned a server error. They now get a clear 415 Unsupported Media Type response.
- The staff app loads faster because feature switches are checked once per request instead of once per use.
- Internal to Canvas Platform and Studio; nothing changes for an instance's users.
- The patient portal refuses oversized sign-in and verification requests sent without a login. Patients and staff see no change.
- Production Canvas instances no longer answer GraphQL schema introspection queries. Day-to-day use of Canvas and the patient portal is unaffected.
