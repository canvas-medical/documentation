Today's release includes the following updates:

<span class="tag-sdk">sdk</span>

- Plugins can now write the patient portal invite and password reset emails. A plugin sets the subject and body, and Canvas adds the login link when the body leaves it out. When no plugin answers in time, patients get the standard email. See [Customize the Login Email](/sdk/patient-portal/#customize-the-login-email).
- Plugins can now search open appointment times with the same search the Canvas booking screens use, filtered by location, provider, visit type, and length. A plugin's own booking screen can offer the same times Canvas does. See [Searching for open appointment slots](/sdk/utils/#searching-for-open-appointment-slots).
- Canvas can now record Diagnose commands as Assess on your instance, so a condition the patient already has isn't added again. Reach out to Canvas support to turn it on.
  - **Plugins:** a [Diagnose](/sdk/commands/#diagnose) a plugin adds is saved as an Assess that reuses the patient's existing condition. Existing plugins work without changes, and handlers receive Assess events for these commands.
  - **FHIR:** a [Condition create](/api/condition/) for a code the patient already has returns an error naming the existing condition, and a new active condition is recorded with an Assess.
- From December 14, 2026, Canvas instances refuse plugin changes the `canvas` CLI sends straight to the instance, such as `canvas install`, and the error points to `canvas deploy`. See [Upgrading to Canvas Platform](/guides/upgrading-to-canvas-platform/).

<span class="tag-config">config</span>

- New Constance config `LEGACY_PLUGIN_INSTALL_CUTOFF` that sets the date an instance stops accepting plugin changes sent straight from the `canvas` CLI.
  - It defaults to December 14, 2026.
  - Reach out to Canvas support to set a later date for your instance.

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where a plugin could reschedule an appointment after the patient was checked in, leaving the visit's note without its sign buttons. The [reschedule effect](/sdk/effect-notes/#reschedule-appointment) now returns a validation error for a checked-in appointment, and the note stays ready to sign.
- Fixed an issue where a note left open in one tab kept saving changes after it was deleted or canceled in another. Changes to a deleted or canceled note are not saved.
- Canvas loads faster, with the largest improvement on repeat visits.
