Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed a bug where FHIR Encounter resources did not have Provenance records created for them.
- Fixed Structured Assessment commands using expired ICD-10 descriptions when creating conditions. The lookup now filters by the note's date of service, ensuring the current ICD-10-CM text is used.
- Expanded the plugin sandbox allow list to include `FloatField`, `Func`, and the standard `html` library.

<span class="tag-sdk">sdk</span>

- FHIR Questionnaire read and search endpoints now support nested `item` objects under the `item` attribute.
- FHIR QuestionnaireResponse read and search endpoints now support nested `item` objects under both the `item` and `answer` attributes, population of the `identifier` attribute and `questionnaireDisplay` extension, a `url` extension for responses to non-FHIR questionnaires, and `valueDecimal` answers.
- FHIR QuestionnaireResponse create and update endpoints now support creating resources that respond to non-FHIR questionnaires (i.e., a questionnaire at an external URL rather than a FHIR Questionnaire resource).
- Added a `commit` parameter to the [`originate()`](/sdk/commands/#originate) command method, allowing plugins to originate and commit a command in a single effect without manually managing UUIDs.
- Added a new `CLAIM_QUEUE_MOVED` SDK event, which emits when a claim moves to a queue. [Read more](/sdk/events/#claims).
- Added the rendering provider address to the ClaimProvider model.
- Updated the patient chart header to support rendering additional action buttons.
- The `upsert_metadata` method on commands can now be chained with `originate()` in the same handler response, allowing metadata to be attached to commands at creation time.
