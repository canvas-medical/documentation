Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where staff password reset links were rejected as invalid on the first click, which kept new staff from setting their first password. Reset links now work the first time they are opened.
- Fixed an issue where a patient statement could print a visit's services and amounts at the top of the next page, apart from the visit's date of service and provider. Each visit's details now stay together on one page.
- Fixed an issue where creating a team in Settings did not save the staff members selected on the form. New teams now keep their members.

<span class="tag-portal">portal</span>

- Plugins can now set a portal menu application as the patient portal's [default home page](/sdk/patient-portal/#configuring-the-patient-portal). Patients who open the portal home page go straight to that application, with any consents, forms, and sign-in modals shown on top of it. If the application is not installed or its plugin is disabled, patients see the standard landing page.
- Fixed an issue where a patient portal user with the direct link to a staff-only plugin application could open it. Patients can now open only enabled [portal menu applications](/sdk/handlers-applications/#who-sees-an-application).

<span class="tag-sdk">sdk</span>

- Plugins can now read these files through the SDK data models, each with a presigned URL property:
  - [Invoice PDFs](/sdk/data-invoice/#accessing-the-statement-pdf)
  - [Business line logos](/sdk/data-business-line/#accessing-the-logo)
  - [Imaging order PDFs](/sdk/data-imaging/#accessing-the-imaging-order-pdf)
  - [Uncategorized clinical document files](/sdk/data-uncategorized-clinical-document/#accessing-the-document-file)
  - [Letter attachment PDFs](/sdk/data-letter/#the-printed-attachments)
  - [Data Integration task documents](/sdk/data-integration-task/#accessing-the-document-file)
