Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Printing a letter whose PDF fails to generate leaves the letter editable, so attachments can be removed and the letter printed again. Letters stay unlocked until their PDF is successfully generated for printing.
- Allowed amounts on postings entered in error are voided along with the posting, so they are left out of allowed-amount reports and exports.
- Reassign now replaces Delegate as the single way to hand off Lab, Imaging, Consult/Referral, and Uncategorized reviews to a person, a team, or both. Providers and licensed staff can choose to release their signature to the recipients. Reviewers can add comments without changing who the document is assigned to, and each document's history now shows reassignments, comments, signature releases, recordings, and entered-in-error actions in one timeline. In review, the SIGN button is now RECORD.
- Fixed an issue where side-panel actions on a line with typed text replaced the text instead of adding their command below that line.
- Fixed an issue where commands added to a note while it was being checked in, locked, signed, or updated by a plugin could disappear from the note body.
- Fixed Review of Systems and Physical Exam commands reverting a plugin's follow-up edit, such as switching answered sections on, after another plugin updated the command.
- Updating a note through the [Note API](/api/note/) keeps the user who created it as the note's originator. The Note and Letter APIs accept only the documented note attributes; other fields in a create or update request are ignored. Responses are unchanged.
- Fixed an issue where commands added from the chart panel could replace typed text on the line where the cursor sat. Commands are now placed next to the cursor line without replacing typed text. A failed add shows an error message, and refill request Approve and Deny buttons reappear after a failure.
- Fixed an issue where note lines added by plugins while a command was being created in the note editor were lost when the note body was saved.

<span class="tag-sdk">sdk</span>

- Calendar events created by plugins — such as the external-calendar busy-block sync — can now be updated and removed correctly. Previously, cancelling or editing a synced event could leave a stale copy on the Canvas calendar that never went away.
- Plugins can now assign a claim to a staff member or a team — and clear that assignment — programmatically through the SDK.
- Care managers can mark where a provider signs and dates a document, then send it for signature. Providers confirm and sign from the review with their own saved signature, and the document returns to the sender. Each send and return shows in the document's history and in its delegation details from the review. Documents also gain Add comment, a single history timeline, and a RECORD commit button.
- Internal: removed 14 empty skipped Cypress stubs from the notes update spec. Each was either deleted because another spec already covers it, or replaced with a real end-to-end test (push charges/view claim, link to phone, SOAP/APSO reorder, print after visit summary, assign note).
- Internal: the ontologies service now runs on Python 3.13 and Django 5.2 LTS (from Python 3.9 and Django 2.2). No change to ontologies API responses or home-app behavior is expected.
- When Canvas deploys to an instance, Canvas Studio's connection to that instance picks up the permissions Studio is approved for, with no manual reconnect.
- When an instance is cloned, Canvas Studio's access to the copy is removed. A lower-environment copy reconnects to Studio through the usual setup.
