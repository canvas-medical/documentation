Today's release includes the following updates:

<span class="tag-ui">ui</span>

- Refill request cards in the refill panel now show who each request is assigned to, and you can reassign it to another prescriber right from the card.
  - Reassigning moves the request to that prescriber's work queue. It doesn't change the prescriber on the refill.
- The Add Condition command now sets the condition's category, continuing the gradual update to how Canvas records conditions. See [Adding a New Condition](https://help.canvasmedical.com/articles/9221634314-new-diagnoses) in the Canvas Help Center.
  - **Category Type:** Problem List Item (the default) or Health Concern.
  - **Category Domain:** an optional SDOH, functional status, disability status, or cognitive status domain.
  - A condition already on the patient's chart, active or resolved, can't be added again. The command points you to Assess Condition instead.

<span class="tag-portal">portal</span>

- Fixed an issue where clicking into a field just as sign-in, registration, or account creation finished could leave the patient on that page. They now continue to the patient portal.
  - If registration or sending a sign-in link fails, the page now asks the patient to reload and try again, instead of leaving the button disabled.

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where printing a note before its Assess Condition was recorded showed that Assess with a blank condition, when the Assess was adding a condition not yet on the patient's chart. The printed note now shows the condition and its ICD-10 code, whether or not the Assess has been recorded.
- Fixed an issue where ICD-10 codes stored with a dot, such as some imported conditions, printed with a second dot (for example, G43..919). They now print correctly, and are sent correctly on electronic lab orders, LabCorp requisitions, and prescription indications.
- Fixed an issue where a recurring calendar event a plugin created with an end date could still show occurrences after that date on the schedule.

<span class="tag-sdk">sdk</span>

- Plugins can now manage refill requests.
  - **Effect:** use [`UpdateRefillRequest`](/sdk/effect-update-refill-request/) to manage a pending refill request: assign it to a prescriber, or ignore it the same as the refill panel's **Ignore** button.
  - **Events:** [react when a refill request is created, updated, or reassigned](/sdk/events/#refill-requests).
  - **Data:** [list the pending refill queue](/sdk/data-refill-request/#pending-requests).
- Plugins can set an [approximate date](/sdk/commands/#approximatedate) to just a year (`"2023"`) or a month and year (`"06/2025"`). Canvas records it the same way as one typed into the chart. This applies to:
  - [Add Condition](/sdk/commands/#addcondition), [Assess](/sdk/commands/#assess), and [Diagnose](/sdk/commands/#diagnose) commands' `approximate_date_of_onset`
  - [Medical History](/sdk/commands/#medicalhistory) command's `approximate_start_date` and `approximate_end_date`
  - [Surgical History](/sdk/commands/#surgicalhistory), [Allergy](/sdk/commands/#allergy), and [Immunization Statement](/sdk/commands/#immunizationstatement) commands' `approximate_date`
  - [Follow Up](/sdk/commands/#followup) command's `requested_date`
- A plugin's [Add Condition](/sdk/commands/#addcondition) for a condition already on the patient's chart stays in the note without recording a duplicate.
- Plugins can now read more records through the SDK data module:
  - [Service requests](/sdk/data-service-request/), which wrap imaging orders, lab orders, referrals, and procedures, with their codings and reason conditions.
  - [Inpatient stays](/sdk/data-inpatient-stay/) and their facilities.
  - [Prior authorizations](/sdk/data-authorization/) and their diagnosis codes.
  - [Letter templates](/sdk/data-letter/#lettertemplate), [lab order specimens](/sdk/data-labs/#laborderspecimen), and [lab value performers](/sdk/data-labs/#labvalueperformer).
  - Codings on [conditions](/sdk/data-condition/#conditioncategorycoding), [allergy reactions](/sdk/data-allergy-intolerance/#reactions), [devices](/sdk/data-device/#codings), [diagnostic reports](/sdk/data-labs/#diagnosticreportcodecoding), [imaging orders](/sdk/data-imaging/#imagingcoding), and [observation components](/sdk/data-observation/#observationcomponentvaluecoding).
