Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where a prescriber who finished DrFirst EPCS enrollment could still have their first controlled-substance prescription rejected at the pharmacy, because their Surescripts directory entry was missing the controlled substance service level and their DEA number. Canvas now ensures the directory entry has both once their enrollment becomes active.
- Fixed an issue where approving a refill request for a controlled substance was rejected after EPCS signing when the original prescription wasn't written in Canvas, leaving the prescription unsent with no error shown. These refills now go through.
  - When a staff member approves a refill on another prescriber's behalf, the response sent to the pharmacy now includes the staff member's name.
- Fixed an issue where the patient portal could suddenly lose its styling, such as showing oversized icons, until the page was reloaded. The portal now keeps its styling.
- Fixed an issue where saving a change, such as collecting a payment, could show a connection error even though the change was saved. Collecting payments, FHIR API writes, signing notes, confirming appointments, and updating commands now complete normally, and plugin events such as `CLAIM_UPDATED` still fire.
- Fixed an issue where a command that a plugin added to a note from a chart application tab didn't show in the note after returning to the Chart tab until the page was refreshed.

<span class="tag-ui">ui</span>

- Assess has a new **Show in problem list** checkbox. Uncheck it when a condition applies only to the current visit, such as a sore throat.
  - The condition is still assessed, appears in billing, and can be linked from Plan commands, but stays off the patient's problem list.
  - Turning it back on in a later visit moves the condition onto the problem list.
- The global Messages panel has a new **Assignee** filter, which replaces the Recipient filter. It defaults to **Me or my teams**, and the unread badge includes messages assigned to your teams.
  - Filter by **Me**, **Me or my teams**, **All**, **Unassigned**, or a specific staff member or team.
  - Plugins assign patient messages to a team. When one team member reads a team message, it's marked read for the whole team.

<span class="tag-sdk">sdk</span>

- Plugins can assign patient messages to a team:
  - `create()` and `create_and_send()` on the [`Message`](/sdk/effect-messages/#methods) effect accept a `team_id` to create a message already assigned to a team.
  - The new [`AssignMessageTeam`](/sdk/effect-messages/#assignmessageteam) effect reassigns or unassigns an existing message.
  - The new [`MESSAGE_TEAM_ASSIGNED`](/sdk/events/#messaging) event fires each time a message's team is set, changed, or cleared.
  - The [Message](/sdk/data-message/#message) data model shows the team a message is assigned to, and [Team](/sdk/data-team/) lists its assigned messages.
- [`AssessCommand`](/sdk/commands/#assess) accepts `show_in_problem_list`, so a plugin can record a condition for the visit without adding it to the problem list.
- Plugins can read a provider's Google Calendar busy time, Google Calendar connection status, and connected calendars through the [Google Calendar data models](/sdk/data-google-calendar/), for providers using [Google Calendar sync](/product-updates/google-calendar-sync/).
- Plugins can read which command types are turned on for an instance through the [`CommandTypeSetting`](/sdk/data-command-type-setting/) data model.
