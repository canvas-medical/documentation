Today's release includes the following updates:

<span class="tag-sdk">sdk</span>

- Plugins can now respond when a claim's balance changes, with the new [`CLAIM_BALANCE_CHANGED`](/sdk/events/#claims) event. Use it to follow payments as they post, or to see when the amount a patient or their insurance owes changes.
  - The event carries the claim's patient and insurance balances from before and after the change.
- Plugins can now import more in the [sandbox](/sdk/sandboxing-and-allowed-imports/):
  - [`secrets`](/sdk/sandboxing-and-allowed-imports/#secrets), for secure tokens and comparisons
  - [`bisect`](/sdk/sandboxing-and-allowed-imports/#bisect), for working with sorted lists
  - [`re.I`](/sdk/sandboxing-and-allowed-imports/#re), and the URL-safe [`base64`](/sdk/sandboxing-and-allowed-imports/#base64) encode and decode functions
  - Django's [`DatabaseError`](/sdk/sandboxing-and-allowed-imports/#djangodb) and the [`Length`](/sdk/sandboxing-and-allowed-imports/#djangodbmodelsfunctions) database function
- Canvas now does plugin work only for the events your instance's plugins actually use. Many actions in Canvas, such as saving a command or opening a chart, raise an event for plugins. When none of your installed plugins listens for that event, Canvas skips it, so those actions finish faster.
  - Events that no plugin listens for no longer appear in the plugin logs.
  - A plugin that is installed, updated, or re-enabled starts receiving its events as soon as it has loaded.
- Fixed an issue where a payment a plugin posted with [`ClaimEffect.post_payment`](/sdk/effect-claims/#post-payment) could be partly saved if posting failed, leaving the payment recorded without all of it applied to the claim's charges. A payment now posts completely or not at all.
