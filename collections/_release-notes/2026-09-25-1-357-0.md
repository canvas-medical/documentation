Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where the default supervising provider dropdown on a staff member in the admin site listed the same provider once for every prescriber role they hold. Each provider now appears once.
- Fixed an issue where removing a pending follow-up appointment request, or closing the Reschedule window without booking, could leave a note showing its previous scheduling status until the page was reloaded. The note's status now updates as soon as the change is made.
- Fixed an issue where a plugin's [SimpleAPI](/sdk/handlers-simple-api-http/) endpoints briefly stopped responding while the plugin was being reinstalled or upgraded. The running version now keeps serving until the new one has loaded, and stays in place if the new version fails to load.

<span class="tag-ui">ui</span>

- A new **Add Condition** command in the note's History section records a coded (ICD-10) condition on the patient's Conditions list as active, without opening an assessment for it. Reach for it when a condition was diagnosed previously and is still active.
  - Diagnose stays the command for an active condition you are assessing for the first time, and Past Medical History for backfilling a condition the patient had in the past that is not active now.
  - The command captures the condition, a background, an approximate date of onset, and comments, and uses the same condition picker as Diagnose.
  - It shows an informational message when the condition is already on the patient's Conditions list.
  - A condition's background now follows its most recent committed assessment, and assessing a condition prefills Background from the condition. Entering the last assessment in error restores the background the condition was recorded with.
- A new **Remove Past Medical History** command in the note's History section takes a committed past medical history entry off a patient's chart and records why.
  - The note that originally recorded the entry is left as it is, so the chart still shows what was documented and when.
  - An entry that has been assessed is not offered for removal, and entering the removal in error puts the entry back on the patient's chart.
- Both commands are switched on for every instance.

<span class="tag-sdk">sdk</span>

- Plugins can now originate, edit, and commit the [Add Condition](/sdk/commands/#addcondition) and [Remove Past Medical History](/sdk/commands/#remove-past-medical-history) commands, alongside the clinicians using them in the note.
  - Add Condition takes an `icd10_code`, and optionally a background, an approximate date of onset, and comments.
  - Remove Past Medical History takes the `condition_id` of a committed past medical history entry on that patient, and an optional rationale.
