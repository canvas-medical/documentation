Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Fixed an issue where labels in the Task command's Labels field were not sorted by position order. Labels now appear in the configured position order.
- Fixed an issue where pasting a long block of text into an autocomplete field triggered shorthand expansion, which could slow down medication and condition search for everyone on the instance. Pasting into autocomplete fields no longer triggers shorthand expansion.
- Fixed a gap that let a plugin commit (sign) a prescription without a prescriber. Plugins can still draft prescriptions — including refills and adjustments — but signing now always requires a licensed prescriber in Canvas.
- Fixed an issue where `.active()` on NewLineItemPayment, NewLineItemAdjustment, and LineItemTransfer raised an error instead of filtering out transactions that were entered in error. Canvas now sends each transaction's entered-in-error status to the SDK, and the fix takes effect once the companion canvas-plugins release ships.
- Fixed an issue where the right chart pane closed when navigating between routes for the same patient. Moving to Documents, Profile, diagnostics, or a full-chart application tab now keeps the pane and whatever a plugin is holding in it, so in-progress work in a pane application survives a tab click. The pane still closes when you switch to a different patient or leave the chart, and pane applications are notified when it closes. Closing the pane on its own leaves a modal that is open at the same time in place.
- Fixed an issue where the SDK views for line item payments, adjustments, and transfers did not include the entered_in_error_id column. Once the matching SDK release ships, `.active()` works on those models and excludes voided transactions, where it currently raises a FieldError.

<span class="tag-sdk">sdk</span>

- Fixed a memory-amplification pattern that caused chart loads for patients with very large condition lists to crash a worker; no user-visible behavior change.
- Removed the unused Audit data-quality framework and its `/api/Audit/` endpoint; the api_audit table is dropped by migration.
- Plugins can now read CustomCommand records (the anchor for the custom_command command), including their patient and note references, through the Canvas SDK data module.
- Plugin developers can now read Clipboard command data — including the associated patient, note, and free-text content — through the SDK data module.
- Fixed a cardinality-driven disk-growth leak on the shared metrics store by removing the ephemeral container host tag from metrics-v2 InfluxDB series.
- Fixed an issue where uv's exclude-newer setting was not pinned in pyproject.toml in both home-app and canvas-plugins, causing the lockfile to flip-flop between developers, CI, and the release job depending on who last touched dependencies.
- Printing a document now leaves an audit record naming who printed it, what was printed, and the patient in context. This covers After Visit Summaries, notes, educational material, letters, appointment lists, schedules, cash reconciliation, claims and superbills, receipts, ledgers, insurance cards, and every command printout. Print activity appears in the admin Audit Report export alongside created, changed, deleted, and access entries. Audit Report entries derived from audit events, including chart access, now show the correct user. They were previously attributed to the wrong person or omitted from the export. Previewing a document in the fax dialog is recorded as a fax preview, shown in the Audit Report with action faxpreview.
- Fixed an issue where Canvas CI installed Node dependencies with package lifecycle scripts on the jest, typescript, knip, and prek jobs, increasing exposure to npm supply-chain attacks that execute code during install. Node dependencies are now installed without running lifecycle scripts. The unused memlab memory-profiling tooling has been removed from home-app.
- Plugins can now read `created` and `modified` on the SDK data models whose views gained the columns, so a plugin can filter and sort on when a record was last changed.
- Mirth administration is now served on a dedicated endpoint restricted to the Tailscale exit node, reachable by the Administrator web UI and the desktop client. The public Mirth endpoints serve the /services channel listener that home-app calls.
- Plugins can now open modals in the patient portal and the staff app: a [LaunchModalEffect](/sdk/effects/) returned from a portal application's `on_open` opens over the portal, and one returned from other handlers, such as a [SimpleAPI](/sdk/handlers-simple-api-http/) route, opens for the signed-in user if their portal or staff app is open. Plugin modals also no longer fail to open when the effect includes fields from a newer SDK version.
- Fixed an issue where the custom report query CI check failed on reports that read plugin custom data schemas, and its test database did not recognize legacy time zone names such as US/Eastern. Both now match production behavior.
- Plugins can no longer programmatically commit (sign) a prescription — a licensed prescriber must sign each prescription in Canvas before it can be sent to the pharmacy. Drafting prescriptions via a plugin for a prescriber to review and sign is unchanged.
