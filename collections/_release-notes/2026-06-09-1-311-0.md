Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue that could prevent letters with malformed attachments from being faxed or printed. Affected letters now generate and send successfully.
- Fixed an issue where editing a staged [Lab Order](/sdk/commands/) via the SDK wiped selected tests when the lab partner was unchanged.
- Fixed an issue where future appointments did not have their status updated to cancelled when a patient was marked as deceased.
- Editing a Facility's address from the admin settings page now refreshes the address on every patient assigned to that facility, so mailing, billing, and reports stay in sync.
- Fixed a defect in Data Integration affecting controls on individual rows when selecting patients.
- Fixed a bug where an appointment provider reassignment through the [FHIR API](/api/appointment/) only updated the Appointment's associated provider and not the corresponding Note's provider.
- Fixed reliability of letter PDF downloads by streamlining memory consumption and catching errors during PDF generation.

<span class="tag-sdk">sdk</span>

- Plugins can now originate and edit a POC Lab Test command via the SDK. [Read more](/sdk/commands/)
- Eliminated spurious "Invalid panel sections received from plugin" errors that were logged whenever a plugin customized the patient or global panel buttons. No change to what is shown on screen.
- FHIR [Appointment](/api/appointment/) search responds faster on instances with many appointments or with multiple reasons-for-visit per note.
- The Lab Orders admin page no longer slows down or causes errors on instances with many staff. The ordering-provider filter is now a name search box instead of a dropdown of every staff member.
- Insurance eligibility check results no longer show spurious "could not match patient/coverage" errors caused by benign formatting differences in the payer's response (capitalization, punctuation, leading zeros, or an abbreviated first name). These responses now correctly display the returned benefit information instead of a failed/error result.
- Plugins that react to a note state change on the post-create [event](/sdk/events/) can now read the acting user (actor), matching the pre-create event. This lets plugin authors move work off the blocking pre-create path without losing the actor.
- Plugin applications now display notification badges.
