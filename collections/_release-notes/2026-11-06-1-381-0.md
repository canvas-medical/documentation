Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Fixed an issue where enabling or disabling a plugin could take up to 5 minutes to show or hide its commands. A plugin's commands now appear or disappear right away.
- Fixed an issue where commands that a plugin adds under an Assess while a clinician is typing in the note did not appear nested under that Assess until the page was reloaded. The commands now appear nested under the Assess without a page reload.

<span class="tag-sdk">sdk</span>

- Plugins can now track patient portal invitations. A new SDK data view shows each invitation's status (pending, opened, claimed, or expired), and new [events](/sdk/events/) fire when an invitation is created, opened, claimed, expired, or rejected, with the reason it was rejected. Plugins can also see when a patient last logged in to the portal.
- The CLI commands `canvas logs`, `list`, `enable`, `disable`, `config list`, and `namespace` sign in through Canvas Platform, so no `canvas` command needs `credentials.ini`.
- Internal: live settings are read and written through django-constance's own database backend, completing the django-constance 4 upgrade. No user-facing behavior change.
- Plugin effects can link a command only to the assessment of a live Assess command in the same note.
- Developers can build a home-app preview with an unreleased canvas-core branch, tag, or commit by adding a `CANVAS_CORE_REF` line to the PR description, the same way `CANVAS_PLUGINS_REF` selects a canvas-plugins branch.
- Scheduled plugin updates (care cards, banners) no longer fail in bulk after a brief database connection drop; only the one in-flight update is affected.
- The staff app no longer downloads an unused payment script on every page, so pages start loading sooner.
