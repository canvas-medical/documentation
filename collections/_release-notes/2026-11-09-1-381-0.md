Today's release includes the following updates:

<span class="tag-sdk">sdk</span>

- Plugins can now follow patient portal invitations, from the moment a link goes out to the patient setting their password.
  - **Data:** read each [portal invitation](/sdk/data-portal-invitation/) and its status: pending, opened, claimed, or expired. Plugins can also see when a patient [last logged in](/sdk/data-canvasuser/#attributes) to the portal.
  - **Events:** react when an invitation is [created, opened, claimed, or rejected](/sdk/events/#portal-invitations), with the reason a link was rejected.

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where a plugin's [custom commands](/sdk/commands-custom-command/) could stay in the note's command menu, or stay missing from it, for up to 5 minutes after the plugin was disabled or enabled. They now appear or disappear right away.
- Fixed an issue where [`patient_id_from_target()`](/sdk/protocols/#key-methods) on a clinical quality measure raised an error for record events such as conditions, lab orders, lab reports, and medications. It now finds the patient for those events.
  - Interview, instruction, referral report, billing line item, and imaging report events are supported too.
- Fixed an issue where a brief connection interruption could make many plugin updates, such as protocol cards and banner alerts, fail at once. Plugin updates now recover more reliably.
- Pages in the provider application start loading sooner.
