Today's release includes the following updates:
Looking at this content, I need to carefully categorize these bullets. Many are security/infrastructure changes, internal changes, or SDK/platform updates. I'll improve the wording while preserving meaning and not inventing links.

<span class="tag-bugfix">bugfix</span>

- The Medication integration message type is no longer accepted; integration messages of that type now receive an unrecognized integration type error.
- Preview environments keep accepting `canvas install` after December 14, 2026, and the Canvas CLI shows the install deprecation notice only for customer instances.

<span class="tag-sdk">sdk</span>

- No user-facing change; this re-enables an end-to-end test.
- No user-facing change; this removes two skipped end-to-end tests.
- `canvas logs`, `list`, `enable`, `disable`, `config list`, and `namespace` now sign in through Canvas Platform, so no `canvas` command needs `credentials.ini`.
- Plugins can see who is using the patient portal on a chart (a family member or the patient themselves) and read the portal access staff gave each family member, area by area.
- When a family member with portal access uses a plugin page on a patient's chart, the Audit Report now records it: who they are, the patient, the plugin, and the request. Audit Report rows for actions patients take in the portal now name the patient instead of leaving the user blank.
- Canvas services no longer trust certificates issued under the eMudhra intermediate certificate authorities whose private keys were exposed, closing a path for impersonating the external services Canvas connects to, including payment processing.
- Canvas no longer accepts sign-in sessions or password reset links signed with a shared development key; each instance uses only its own key.
- Prescription data in the shared pharmacy service is now visible only to the customer it belongs to, and the pharmacy service's eligibility, benefits, and medication history lookups require authentication.
- Canvas now refuses two kinds of malformed API requests that could tie up the server. Normal browser and integration traffic is unaffected.
- Banners that plugins add when you push charges or lock a note now show up on the patient's chart right away, without reloading the page.
- On instances that run the janus regression agent, its login can see and change Canvas-managed Constance settings. Customer instances are unchanged.
- In the revamped note, a Structured Assessment can be nested under an Assess Condition in the same note: drag it onto the Assess to nest it, or drag it out to unlink it. A nested Structured Assessment prints under its Assess, and moves back to the top level if the Assess is entered in error. Plugins can link a Structured Assessment to an Assess with `assessment_id`. Plugins that create or edit a [Questionnaire](/sdk/commands/#questionnaire), [Review of Systems](/sdk/commands/#review-of-systems), [Physical Exam](/sdk/commands/#physicalexam), or Structured Assessment with answers keep the other fields they send.
- The patient chart responds faster and makes fewer background requests. It no longer re-renders on unrelated activity in the app.
- E-prescriptions and medication history requests no longer fail when a patient's street address has a line break in it.
- Malformed requests to the OAuth authorization page, including a SMART launch value that cannot be decoded, now get an error response or an `access_denied` redirect instead of a server error.
- Messages from patients, staff, plugins, and integrations are cleaned of scripts, event handlers, and page-covering styles before they are stored and when they are shown. Formatting, links, and inline images in messages are kept. Form fields pasted into a message, such as a copied Refill command card, keep the values they show as text.
- Plugin APIs, plugin application events, the companion app, and the OAuth consent screen now ignore requests that another website makes your browser send while you are signed in to Canvas. Plugin pages, API keys, and OAuth tokens work as before.
- Internal CI change: diagnostic settings dumps attached to failed test runs no longer contain credentials. No user-facing change.
- Remembered multi-factor sign-ins are tied to the Canvas instance where they were made. After this release, users who chose to be remembered enter their second factor once more.
- Staff users limited to some patient groups can no longer view or change records (tasks, medications, documents, billing records, notes, appointments, letters, and more) for patients outside their groups. A record outside the user's groups behaves as if it does not exist, and the patient statements batch includes only the requester's patients.
- Staff API endpoints for patient search, addresses, coverage, balances, settings, parent/guardian details, documents, care team, and linkable lab orders now require the same permissions as the matching screens in Canvas, and only answer for patients in the user's patient groups.
- Staff API endpoints across the chart, orders, prescriptions, labs, printing, faxing, and billing now require the same permissions as the matching screens in Canvas, and only answer for patients in the user's patient groups.
- Tightened permissions: the schedule's appointment status menu can now only cancel an appointment or mark a no-show, booking a follow-up only reuses that patient's open appointment note, and patient portal sign-in links stay limited to the patient's own chart. Plugins can no longer sign prescriptions.
- Staff users now need the matching role permissions to read clinical, patient, task, and revenue data through the app's data API, the same permissions the REST API requires. The schedule is unchanged.
- Staff limited to some patient groups no longer reach another group's patients through the connected payment account lookup, the appointment scheduling forms, or the data integration inbox's document actions.
