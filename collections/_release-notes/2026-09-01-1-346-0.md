Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Fixed an error in the Canvas Remote app that blocked capturing insurance card images when adding a new coverage. The front and back card-capture steps now load correctly for a newly started coverage instead of failing.
- Fixed a FieldError raised when calling `find()` with a value set on [FamilyHistory](/sdk/data-family-history/) and ImmunizationStatement records in plugins; these value-set lookups now return results correctly.
- Discharging an inpatient note now records a single lock entry in the note's state history and emits one corresponding note state change event.

<span class="tag-sdk">sdk</span>

- Questionnaires now support a Date question type. Authors can add it in the questionnaire builder, and responders answer with a date picker — the captured date flows through charting, carry-forward, inbound QuestionnaireResponse integrations, and the API.
- Plugins can now read [Plan](/sdk/data-plan/) data — the anchor for the plan command — through the Canvas SDK data module, including both the narrative and narrative_json content.
- [FollowUp](/sdk/data-follow-up/) is now available in the SDK data module, letting plugin developers query follow-up records — including patient/note, requested appointment date, reason for visit, note-to-patient and internal comments, and the requested appointment/note types.
- The Canvas SDK data module now exposes Remove Allergy events, letting plugin developers read a removed allergy along with its patient, note, and rationale.
- Plugin developers can now query Resolve Condition events through the SDK data module, including the linked condition, patient, note, and rationale.
- Plugins built on the Canvas SDK can now read Reason for Visit records through the data module — including the patient, note, narrative text, and the visit's reason-for-visit codings.
