Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Fixed an issue where SSO failed when a duplicate Staff record with the same email address existed and one was inactive. The login flow now correctly resolves to the active Staff record.
- Fixed an issue where closing a side panel (such as a Task) opened from a permalink or deep link did nothing — the panel would immediately reopen, and the only workaround was switching tabs. Clicking the X now closes the panel as expected.
- Fixed an issue where inbound faxes could stop being received when the fax provider returned a transient gateway error (the poller now skips and retries instead of crashing). High-volume accounts now reliably receive every inbound fax, since the poller pages through the full fax history rather than only the first page.
- The "New note" type dropdown now scrolls instead of extending off-screen behind Canvas Chat on instances with many note types.
- Fixed a bug where adding a coverage to a claim did not use the most updated subscriber ID.
- Fixed an issue where a provider without an NPI creating a billable note could leave behind a broken note with no state. Note creation is now atomic, so it fully succeeds or rolls back cleanly with no orphaned notes.

<span class="tag-sdk">sdk</span>

- Redis and RabbitMQ connections now detect stale or dead pooled connections proactively via health checks, keepalives, and a Celery broker heartbeat, reducing intermittent "Connection reset by peer" errors during business hours.
- Reduces server memory growth under heavy load by using the jemalloc memory allocator (enabled per instance), lowering the chance of out-of-memory container restarts.
- Health Gorilla diagnostic reports are now filtered by patient as well as recipient NPI, so customers running multiple Canvas instances against a shared Health Gorilla account no longer ingest results for patients that belong to a sibling instance.
- Internal: Cypress CI runs ~25% faster (slowest matrix group 15:35 → 11:40) via SeedPatient caching, workflow setup parallelism, and test sharding. No user-facing change.
- Internal: upgraded mypy to 2.1 and turned on parallel type checking to speed up the home-app type-check step. No user-visible behavior change.
- Plugins can now look up DiagnosticReport(s) linked to a Lab Report, fetch a DiagnosticReport by its ID and follow it back to the originating Lab Report, and filter DiagnosticReports by patient via the new DiagnosticReport view in the SDK data module.
- Fixed an intermittent error that could block creating or signing a note and show "an error occurred loading this note" — most often after a browser tab had been left in the background or the browser discarded it.
- The SDK data module now exposes report-level lab remarks (`LabReport.remarks`) and imaging report coding detail (`ImagingReport` → `ImagingReportCoding`), so plugins can surface the same lab and imaging review detail shown in the Canvas UI.
- Internal: home-app's serve.sh now reads the deploy image (Grafana startup annotation) and request idle timeout from non-reserved vars (`DEPLOYED_IMAGE`, `APP_IDLE_TIMEOUT`) so they survive Aptible's 0.10.x migration, keeping legacy `IDLE_TIMEOUT`/`APTIBLE_DOCKER_IMAGE` as fallbacks; also makes knip deterministic across worktrees. No customer-visible behavior change.
- Internal: removes the obsolete GitFlow workflow that auto-created merge PRs to production and develop from emergency/* and support/* branches. No customer-facing impact.
- Internal: home-app reads the deploy image tag and request idle timeout from non-reserved Aptible vars (`DEPLOYED_IMAGE`/`APP_IDLE_TIMEOUT`, legacy names kept as fallbacks) for the provider 0.10.x migration, and declares webpack entry points in knip config to fix a worktree-only pre-push failure. No customer-visible behavior change.
