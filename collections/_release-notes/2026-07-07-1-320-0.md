Today's release includes the following updates:


<span class="tag-bugfix">bugfix</span>

- Patient addresses created or updated through a plugin now save the correct US state. Previously the state could be dropped or stored incorrectly when an address was written via a plugin effect.
- Fixed an issue where letters did not remain locked after being printed and remained editable from a different user's session.
- Fixed a Google Calendar sync issue that caused events not to be synced when any calendar on an instance was not found via the Google API.
- Restored compatibility with plugins that look up chart commands by their manifest schema_key. Plugin custom commands installed after release 1.312.0 were stored with an internal version suffix on chart command rows and note bodies, breaking plugin code that filtered by the bare schema_key. Existing chart entries are migrated back to the bare key automatically on deploy.
- Deleting an appointment via the SDK is now idempotent and will no longer raise an exception.
- Further optimizations of the Claims page to improve load times.

<span class="tag-sdk">sdk</span>

- All committable command SDK data model managers now support a `committed()` convenience method: Assessment, ChartSectionReview, DetectedIssue, Device, Goal, ImagingOrder, ImagingReview, Immunization, ImmunizationStatement, LabOrder, LabOrderReason, MedicationStatement, NoteTask, Referral, StopMedicationEvent, and VisualExamFinding.
- Deleted and canceled appointments now display more context in their header — the appointment title, date and time of service, and provider — making it easier to tell which appointment was removed.
- The Questionnaire Builder is now turned on automatically for newly provisioned instances, so teams no longer need to enable it manually during onboarding.
- Multi-factor authentication is now enforced for the API and GraphQL, not just the web UI. A session signed in with only a password can no longer read data until the second factor is completed.
