Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Refill and Adjust from the chart's Medications list now prefill the medication's current directions, including any updates made with Change Medication.
- On instances without SSO, staff who have never had a password, such as accounts created by an integration, can set one from the Forgot password link on the login page.
- Exception stack traces in application logs show a standard traceback and omit the values of local variables, so credentials and patient data held in those variables are not written to the log pipeline.

<span class="tag-sdk">sdk</span>

- Plugins can now white-label the patient portal, including the login page. They can set the brand color, menu colors, page background, corner radius, font, the word used for the person (patient, member, or client) and custom CSS, and the theme can differ per business line. Portals with no theme plugin look the same as before.
- Hardened how single sign-on matches an identity provider login to a Canvas account. Canvas support signs in to the shared support account on each instance only through Canvas's Okta single sign-on with a second factor, and every such sign-in records which person used it.
- Security audit events sent to your SIEM now include which fields an update changed (names only, never values), the plugin and handler behind a change, the instance and whether it is production or non-production, the admin behind an impersonated session, and a reason code for denied requests and failed sign-ins. The Audit Report now names the admin who created a staff account or changed its permissions, instead of the account that was changed.
- Canvas Studio can set up Health Gorilla, DrFirst, and Documo fax credentials on an instance. Replacing a stored lab or fax account still needs a Canvas admin.
- Canvas exposes a versioned configuration API for Canvas Studio, so Studio can configure roles, settings, and common admin records without driving the admin pages.
- Fixed an issue where choosing a population health protocol could briefly show a "Start campaign" button that opened a broken page. Fixed an issue where clicking a filter on another page right after the schedule loaded could send you back to the schedule. Opening a new campaign link for a protocol that no longer exists now returns to the populations list instead of showing an error. Changing the schedule date, view, or provider while a location change is saving no longer gets reverted.
- Integration credentials saved on an instance's settings page, and other credential fields in multipart form submissions, are redacted from request logs.
- Importing a CSV file in the admin (fee schedule, payor-specific charges, vaccines, lab tests, DME products) requires permission to add and change those records, and exporting requires permission to view them.
- Automated abuse blocking now lifts on its own within minutes instead of persisting, so a shared office IP that tripped it regains access. Scanners probing for WordPress, CGI, Subversion, and PHP/ASP/JSP pages are blocked, and signed-out visitors no longer see build or commit details.
- When a plugin or integration re-sends an observation that hasn't changed, Canvas no longer rewrites it. This keeps large re-syncs from slowing the instance and stops plugins from getting update events when nothing changed.
- Request logs and the security audit ledger now record which staff member, patient, or API client made each plugin API call, instead of logging every call as anonymous.
- Canvas now checks that the scripts and stylesheets it loads from content delivery networks have not been altered, and blocks any that have. Gainsight product analytics has been removed from the provider app.
- Removed an unused internal API route that could return a user's outstanding login links to a caller holding a shared service key. Login links, patient portal invites and resets, and the Canvas Cam QR code login are unaffected.
- No user-facing change. Local clinic builds (build_canvas_clinic) need CLAIM_MD_CLEARINGHOUSE_ACCOUNT_KEY in .env; the value is in the AWS Secrets Manager secret prod/home_app/shared.
- The login page now enforces Canvas's Content Security Policy, which blocks unapproved scripts and resources from loading there. The in-app Pylon support widget is no longer blocked by the policy.
- No user-facing change. Fixes a failing end-to-end test for the Order DME command.
