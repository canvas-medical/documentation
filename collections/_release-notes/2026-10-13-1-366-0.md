Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where, when a Fee Schedule has more than one active entry for the same CPT code, charges added from the note footer billing search or from a Perform command could fall back to a different entry with the same code and bill the wrong amount. Charges now bill the entry you selected, and claim lines keep that entry's amount when the claim is repriced (for example, after a primary coverage change).
- Fixed an issue where portal pre-visit assessments (PHQ-9, GAD-7, MADRS, etc.) on the Patient Chart summary displayed the upcoming appointment date rather than the date the patient completed them. Assessment scores now appear with their completion date on the clinical summary and trend graphs.
- Fixed an issue where entering a Perform command in error did not remove the associated CPT codes from the billing footer of a note. The CPT codes are now removed when the command is entered in error.
- Fixed an issue with Surescripts SPI registration where the customer's go-live date could not be carried as the registration's start date. The go-live date can now be set as the start date, which Surescripts asks for at enrollment. A past date or a value that is not a date string is refused. Without a date, the registration starts at submission, as before.
- Fixed an issue where practice location names were not escaped on admin pages. Admin pages now escape practice location names.
- Fixed an issue where review queues failed to load and list documents that have no clinical date. Review queues now load these documents.
- Fixed an issue in the sectioned note where commands could not be reordered by dragging a grip in the left margin, and some fields inside a command, including multi-select dropdowns like Prescribe Indications, did not open on click. Commands can now be reordered by dragging, and every field opens on click.
- Fixed an issue in the new note editor where a custom panel or prefilled fields that a plugin adds to a newly added command did not show right away. These now appear without a page refresh.

<span class="tag-sdk">sdk</span>

- In the revamped note, commands that are not yet committed can be collapsed by clicking their header, and they stay collapsed after a reload until they are expanded, committed, entered in error, or deleted.
- Plugins can now send patients to another page in the patient portal with [RedirectEffect](/sdk/effect-redirect/): an enabled portal page, a portal menu app, or an allowlisted external URL. Other targets are blocked and logged.
- Fixed an issue in the note footer where clicking Done on a billing line item and then quickly clicking into the CPT search or another line item reopened the line item you just closed. The line item now stays closed.
- Instance deploys and restarts finish faster because the SDK database views are rebuilt once at startup instead of once per application.
- Instance deploys and restarts finish faster because startup runs its setup steps in a single process.
- Fixed an issue where visiting /settings showed a server error instead of a standard "page not found" page. To reach settings, use the Settings item in the navigation menu.
- Patient self-registration is refused when the practice has it turned off, is rate limited, and gives one message when an email, phone number, or username is already in use.
- Non-superuser admins cannot change their own roles, groups, or permissions, or edit a superuser's records, which open read-only.
- Only superusers and staff with the Administrative Developer or Clinical Developer role can register OAuth applications.
- `client_credentials` tokens need the `system/*.*` scope to use the `/api` endpoints.
- Claims, claim line items, and eligibility responses over REST require Revenue access and show only patients the user may see.
- Each instance signs sessions and patient portal tokens with its own keys; patient portal users sign in again once after the upgrade.
