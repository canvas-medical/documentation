Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where scanning a link-phone QR code with the Canvas Remote app showed "Invalid QR. Try Again." on instances with multi-factor authentication enabled, so insurance and ID card photos never reached the patient's chart. Scanning now links the phone and the photos upload to the chart. The QR code for capturing exam photos works the same way.
- Fixed an issue where changing an existing appointment's visit type, reason for visit, or duration without moving its start time failed with "The appointment starting at ... is no longer available" on instances with double booking turned off. The appointment now keeps its own time slot, which stays selected in the reschedule window, and Book is enabled once you change something.
- Fixed an issue where opening a permalink to a Letter or Message note showed "Something went wrong" instead of the patient chart. Permalinks now open the chart and scroll to that note.
- Fixed an issue where Canvas could stop loading pages when many browser tabs were open on the instance at once, such as during a training session. Open tabs no longer use up the capacity Canvas needs to load pages.
- Fixed an issue where a FHIR [Practitioner](/api/practitioner/) update that added a new email was rejected with "Emails must remain the same". New emails can be added at rank 2 or higher. The rank 1 email, where password reset links are sent, must be one the practitioner already has.

<span class="tag-ui">ui</span>

- Assess can now diagnose new conditions. Its search lists the patient's charted conditions first, each labeled Active or Resolved, followed by the full ICD-10 list.
  - Assessing a condition that's already charted reuses it instead of adding a duplicate, and makes it active again if it was resolved.
  - Assess has an optional approximate date of onset.
  - Entering an Assess in error also enters in error the condition it added to the chart, unless another assessment still uses that condition.

<span class="tag-sdk">sdk</span>

- [AssessCommand](/sdk/commands/#assess) can name its condition by ICD-10 code with `icd10_code`, as an alternative to `condition_id`, so plugins can assess a condition the patient doesn't have charted yet. It also accepts `approximate_date_of_onset`.
- Picking an ICD-10 code the patient doesn't have charted in an Assess sends the new [`ASSESS_COMMAND__ICD10_CODE_SELECTED`](/sdk/events/#assess_command__icd10_code_selected) event. `ASSESS_COMMAND__CONDITION_SELECTED` now fires only when a charted condition is picked, and always carries its condition id.
- Plugins can link Prescribe, Refill, Adjust Prescription, Change Medication, Lab Order, Imaging Order and Refer commands to an Assess in the same note with `assessment_id`.
  - Linking adds the assessed condition to the command's indications (Lab Order: diagnosis). Change Medication is linked without changing its codes.
  - A prescription that already lists two other indications can't be linked until one is removed.
  - The Prescription, ChangeMedication, LabOrder, ImagingOrder, Referral and EducationalMaterial data models expose the link as `assessment`, and an [Assessment](/sdk/data-assessment/#commands-linked-to-an-assessment) lists the commands linked to it.
- Plugins can render HTML that came from patients or integrations without running scripts in it, using the new [`sanitize_html`](/sdk/utils/#sanitizing-untrusted-html) function or `|sanitize_html` template filter. It keeps basic formatting and links and removes everything else.
