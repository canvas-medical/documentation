Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Fixed an issue where linking a phone by QR code failed on instances with multi-factor authentication enabled. Staff can now capture insurance and ID cards from the Canvas Remote app and have them land on the patient's chart.
- Fixed an issue where changing an existing appointment's duration without moving its start time was rejected on instances that have double booking disabled. The reschedule failed with "The appointment starting at ... is no longer available" because the appointment being rescheduled was counted as a conflicting appointment against itself. The appointment is no longer counted against itself.
- Fixed an issue where opening a permalink to a Letter or Message note did not navigate to the note. Permalinks now open the patient chart and scroll to that note.

<span class="tag-sdk">sdk</span>

- [Assess](/sdk/commands/) can now diagnose new conditions. Its search lists the patient's charted conditions, each labeled Active or Resolved, followed by the full ICD-10 list. Assessing a condition that's already on the chart reuses it, reactivating it if it was resolved, instead of adding a duplicate. Assess also has an optional approximate date of onset. Entering in error an Assess that recorded a new condition also enters that condition in error. For developers: AssessCommand accepts `icd10_code` (as an alternative to `condition_id`; a command sends one of the two) and `approximate_date_of_onset`. Picking a new ICD-10 code in Assess sends the new `ASSESS_COMMAND__ICD10_CODE_SELECTED` event with the picked codings; `ASSESS_COMMAND__CONDITION_SELECTED` fires for charted conditions and carries the condition id.
- With Note Revamp on, the printed care-team note (and its fax and locked-note copy) shows a single Assessment & Plan section: each assessment is followed by the orders, prescriptions, plans and procedures linked to it, indented beneath it, and unlinked items follow at the end.
- In the revamped note UI (behind the note-revamp:enabled switch), Plan and Procedure commands now appear nested under the Assessment they're linked to. You can drag a command onto an Assessment to link it, or drag it out to unlink it, and the change shows up live for everyone who has the note open.
- Internal: removes the broken Lighthouse CI workflow and its unused frontend performance scripts and dependencies.
- Studio's admin bot can sign in to the admin with its OAuth client credentials instead of a password, including on instances that require MFA.
- Internal: Feature flags and switches can now be carried from one instance to the next through promotions, so they no longer have to be copied by hand.
- Fixed an issue where an instance with many browser tabs open at once could stop loading pages.
- Prescribe, Refill, Adjust Prescription, Change Medication, Lab Order, Imaging Order, Refer and Educational Material can be nested under an Assess in a note by dragging them onto it. Nesting a prescription or order under an Assess adds the assessed condition to its indications (Lab Order: diagnosis). A prescription that already holds two other indications can't be nested until one is removed. Plugins can make the same link with `assessment_id`.
- Patient self-registration is refused when the practice has it turned off, is rate limited, and gives one message when an email, phone number or username is already in use. Non-superuser admins cannot change their own roles, groups or permissions, or edit a superuser's records, which open read-only. Only superusers and staff with the Administrative Developer or Clinical Developer role can register OAuth applications. `client_credentials` tokens need the `system/*.*` scope to use the `/api` endpoints. Claims, claim line items and eligibility responses over REST require Revenue access and show only patients the user may see. Each instance signs sessions and patient portal tokens with its own keys; patient portal users sign in again once after the upgrade.
- Canvas Platform can now turn an installed plugin on or off, and promotions keep each plugin on or off to match the source instance.
