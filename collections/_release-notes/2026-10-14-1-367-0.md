Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where scanning a link-phone QR code with the Canvas Remote app showed "Invalid QR. Try Again." on instances with multi-factor authentication enabled, so insurance and ID card photos never reached the patient's chart. Scanning now links the phone and the photos upload to the chart. The QR code for capturing exam photos works the same way.
- Fixed an issue where using the reschedule modal to change an appointment's details without changing its time failed with "The appointment starting at ... is no longer available" on instances with double booking turned off. You can now use the reschedule modal to change an appointment's visit type, reason for visit, duration, or other details and keep the same time. The current time slot stays selected, and Book is enabled once you change something.
- Fixed an issue where opening a permalink to a Letter or Message note showed "Something went wrong" instead of the patient chart. Permalinks now open the chart and scroll to that note.
- Fixed an issue where Canvas could stop loading pages for everyone on an instance when many browser tabs were open at once, such as during a training session. Tabs and plugins that stay connected for live updates no longer take up the capacity Canvas needs to load pages.

<span class="tag-ui">ui</span>

- One command for every condition: Assess Condition now handles brand-new diagnoses as well as conditions already on the chart. Clinicians can diagnose and assess in a single step, and the Conditions list stays free of duplicates. See [Assessing and Updating Conditions](https://help.canvasmedical.com/articles/7989321964-Assessing-and-Updating-Conditions).
  - Its search lists the patient's charted conditions first, including resolved ones, each labeled with its status, followed by the full ICD-10 list.
  - Picking a charted condition reuses it, and a resolved condition becomes active again. Picking a new ICD-10 code adds the condition to the Conditions list.
  - Assess Condition has an optional Approximate Date of Onset. It is saved on the condition and fills in on future assessments of that condition, like Background.
  - Entering an Assess Condition in error also enters in error the condition it added to the chart, unless another assessment still uses that condition.
  - Existing notes are unaffected. Diagnose remains available for now, and we plan to retire it in a future release. See [Diagnosing a New Condition](https://help.canvasmedical.com/articles/9221634314-Diagnosing-a-New-Condition).

<span class="tag-sdk">sdk</span>

- Plugins can now use the new, enhanced Assess Condition. Just pass `icd10_code` to [AssessCommand](/sdk/commands/#assess) and Canvas works out the rest: if the patient already has that condition it's reused (an active one first, and a resolved one becomes active again), and if not it's added to the Conditions list. No more looking up a `condition_id` first.
  - `AssessCommand` also accepts `approximate_date_of_onset`, which is saved on the condition.
  - `condition_id` still works, so existing plugins keep running unchanged.
  - Use `AssessCommand` with `icd10_code` for new work. `DiagnoseCommand` will be deprecated when the Diagnose command is retired. See [Choosing Between Similar Commands](/sdk/commands/#choosing-between-similar-commands) for a refresher on which command to use when charting conditions.
- Assess Condition sends a new [`ASSESS_COMMAND__ICD10_CODE_SELECTED`](/sdk/events/#assess_command__icd10_code_selected) event when its condition is set to an ICD-10 code that isn't charted yet, whether a clinician picks it or a plugin edits the command. [`ASSESS_COMMAND__CONDITION_SELECTED`](/sdk/events/#assess_command__condition_selected) now fires only for a charted condition and always carries its condition id.
  - Neither event fires when a plugin originates an Assess Condition with the condition already set.
- Plugins can link [Prescribe](/sdk/commands/#prescribe), [Refill](/sdk/commands/#refill), [Adjust Prescription](/sdk/commands/#adjustprescription), [Change Medication](/sdk/commands/#changemedication), [Lab Order](/sdk/commands/#laborder), [Imaging Order](/sdk/commands/#imagingorder) and [Refer](/sdk/commands/#refer) commands to an Assess in the same note with `assessment_id`.
  - Linking adds the assessed condition to the command's Indications. Change Medication has no Indications field, so linking it records only the link.
  - Prescribe, Refill and Adjust Prescription allow at most two indications. If a prescription already lists two other indications, linking it fails with "This command holds at most 2 indications. Remove one to link it to this Assess." Remove an indication first, then link it.
  - The [Prescription](/sdk/data-prescription/#prescription), [ChangeMedication](/sdk/data-change-medication/#changemedication), [LabOrder](/sdk/data-labs/#laborder), [ImagingOrder](/sdk/data-imaging/#imagingorder), [Referral](/sdk/data-referral/#referral) and [EducationalMaterial](/sdk/data-educational-material/#educationalmaterial) data models expose the link as `assessment`, and an [Assessment](/sdk/data-assessment/#commands-linked-to-an-assessment) lists the commands linked to it.
- Plugins can safely display HTML from patients or integrations, such as portal messages, with the new [`sanitize_html`](/sdk/utils/#sanitizing-untrusted-html) function or `|sanitize_html` template filter. It keeps basic formatting and links and strips anything that could run code in a staff member's browser. Use it in place of `|safe` for content Canvas staff didn't write.
