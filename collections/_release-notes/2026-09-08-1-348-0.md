Today's release includes the following updates:

<span class="tag-sdk">sdk</span>

- A note's [`body`](/sdk/data-note/#understanding-the-note-body-structure) is now a read-only property rather than a stored field. Reading it is unchanged, and it still returns the same array of text and command objects, but Canvas now assembles it from more than one column, so [fewer query operations can name it](/sdk/data-note/#querying-on-the-body).
  - `filter()`, `exclude()` and `get()` on `body` still work, including lookups nested in a `Q` object, and so do `only("body")` and `defer("body")`.
  - `values("body")` and `values_list("body")` now raise a `FieldError` that points you at `only("body")`, because no single column holds the value they would return. Sorting on `body`, and reaching it from another model's queryset such as `Command.objects.filter(note__body=...)`, are no longer resolved either.
  - Read the body from a note you already have, or filter notes by it, rather than selecting it as a value.
