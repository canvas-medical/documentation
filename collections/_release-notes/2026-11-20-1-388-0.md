Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Recurring calendar events created by plugins with an end date now stop on that date, including after the recurrence backfill runs, instead of repeating indefinitely.
- A printed note now shows the condition and ICD-10 code of an Assess that diagnoses a new condition, even before the Assess is committed.
- Plugins can set an approximate date, such as a history item's date or a condition's onset, to just a year or a month and year, and Canvas records it the way it records one typed into the chart. Canvas Scribe's history suggestions dated only by year or month now add to the note.
- Long team names now show in full in the task list's Team picker and the note header's assign picker.

<span class="tag-sdk">sdk</span>

- Refill request cards in the worklist now show who the request is assigned to and let you reassign it to another prescriber inline, without leaving the worklist. Plugins can also react to and drive refill request assignee changes through new [effect](/sdk/effects/) and [data-change event](/sdk/events/) types.
- Plugins can now read inpatient stays and facilities, lab order specimens, lab value performers, prior authorizations (including their charges and diagnosis codes), and letter templates through the SDK, so they can resolve related records such as a note's inpatient stay or a letter's template.
- Plugins can ignore a refill request with `UpdateRefillRequest(ignored=True)`, the same as the refill panel's Ignore button, and list the refill queue with `RefillRequest.objects.pending()`.
- The [Add Condition](/sdk/commands/) command can now record a health concern and an optional category domain (SDOH, functional, disability, cognitive). It refuses a code already on the patient's chart, active or resolved, and points to Assess instead.
- Preview environment tooling no longer stores AWS credentials in its shared configuration and downloads only the configuration for the preview it is working on.
- Patient portal sign-in, registration, and account creation reliably continue to the portal after success, even if the patient clicks into a field while the request finishes.
- Plugins can now read the codings attached to several clinical records already available in the SDK data module: condition category codings, allergy reactions, device codings, diagnostic report category and code codings, imaging codings, and observation component value codings. The matching models arrive in an upcoming canvas-plugins SDK release.
- Plugins can now read service requests (the FHIR wrapper over imaging orders, lab orders, referrals, and procedures) through the SDK data module. This includes their category and service codings and their linked reason conditions. Plugins no longer need to call the FHIR API or rebuild service requests from individual orders.
- Background workers use less memory while running scheduled jobs, which reduces worker restarts on smaller instances.
- The nightly note migration uses less worker memory and can run longer each night, which reduces worker restarts during the migration.
