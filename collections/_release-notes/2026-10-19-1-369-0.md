Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where custom commands added by plugins were missing from note printouts, faxes, and the PDF saved when a note is locked, unless someone had opened the note in the chart first. They now appear every time.

<span class="tag-sdk">sdk</span>

- Plugins receive [events](/sdk/events/#faxed-documents) when a note, referral, imaging order, lab order, or data integration task is faxed and when its delivery outcome comes back, the same way letter faxes already work. A plugin can react to a failed fax right away, for example to retry it or alert staff. See [Reacting when a fax fails](/sdk/data-fax/#reacting-when-a-fax-fails).
  - Fax status update events, letters included, fire only when the delivery outcome changes, so plugins no longer get repeated events while a fax is pending or when the same outcome is reported twice.
- Plugins can read which staff members a report or document is assigned to for review, and filter by assigned reviewer. This covers [lab reports](/sdk/data-labs/#finding-lab-reports-assigned-to-a-reviewer), [imaging reports](/sdk/data-imaging/#review-assignment), [referral reports](/sdk/data-referral/#review-assignment), [uncategorized clinical documents](/sdk/data-uncategorized-clinical-document/#review-assignment), and [patient administrative documents](/sdk/data-patient-administrative-document/#review-assignment).
  - Lab reports and imaging reports also show the team they're assigned to, as referral reports and documents already did.
- Plugins can read your DME formulary and signed DME orders with the new [DmeProduct and DmeOrder](/sdk/data-dme/) data models, so an [Order DME command](/sdk/commands/#orderdme) can look up a product by its code instead of using a hard-coded ID.
