Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where a [Slot](/api/slot/) search returned no availability for a visit type after that visit type was edited. A search filtered by the edited visit type no longer matched the schedule time Canvas had already read from the practice's calendar, so it came back empty even though the provider was open for it. A visit type now matches its availability whether the calendar was read before or after the edit.
- Fixed an issue where creating a note through the [Note API](/api/note/) could fail with a server error and save no note for a few minutes while a Canvas release rolled out to the instance. These requests now succeed throughout a release.
- Fixed an issue where a command line in a note's [`body`](/sdk/data-note/#understanding-the-note-body-structure) lost its `command_uuid` once the note moved to the [refactored body structure](/release-notes/note-v2-2026-09-15/), leaving a plugin walking the body with no way to resolve a line to its command. Every command line carries `command_uuid` again, whichever structure the note uses.
  - A command line on a note using the refactored structure carries `command_uuid` alone. The integer `id` that some command lines on a legacy note also carry is not present, so read the [Command](/sdk/data-command/) through `command_uuid` and take `anchor_object` from it.

<span class="tag-sdk">sdk</span>

- The plugin runner no longer writes a log line for each handler that runs and each event it handles, so [`canvas logs`](/sdk/canvas_cli/#canvas-logs) and the plugin log viewer show your plugin's own `log` output without two lines per handler in between.
  - Everything on a failure path still logs: a handler that raises an exception, and a handler that returns nothing from `compute()`.
  - Plugin load, reload, unload, and synchronization lines are unchanged.
