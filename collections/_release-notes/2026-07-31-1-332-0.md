Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Fixed an issue where delegating patient communication on a Review, Image, or Refer command could fail to create the follow-up task when no team was set up to own it. These commands now always create the delegated task and assign it using a clear fallback order: to the responsible team when one exists, otherwise to the patient's care team lead, and if there is no care team lead, to the staff member who signed the command. Review commands (lab, imaging, uncategorized document, and consult report review) assign the task to a team with the "Communicate diagnostic results to patient" responsibility. Image and Refer commands assign the task to a team with the "Coordinate referrals for a patient" responsibility.
- Fixed an issue where changing an uncategorized clinical document's type to a Lab or Imaging Report left the original uncategorized document active in the review queue, creating a duplicate. The original document is now retired automatically so it no longer lingers alongside the newly created report.
- Fixed an issue in Data Integration where changing an uncategorized clinical document's type to a Lab Report or Imaging Report left the original document behind in the review queue. The original is now retired automatically, the reviewer's "to review" badge count updates immediately, and the edit-report modal no longer gets stuck open after switching a document's type.

<span class="tag-sdk">sdk</span>

- Task labels are now scoped to the area where they're used. Labels applied to tasks — including the system-generated "Chart PDF" and "Batch Statements" labels — are associated with the Tasks area, so they appear and are selectable in the Tasks label filter. Existing labels continue to work everywhere as before.
- Marking an appointment as no-showed from the calendar appointment card's status dropdown now fires the APPOINTMENT_NO_SHOWED plugin event, so plugins and automations that respond to no-shows trigger as expected. Previously this only worked when marking a no-show from the patient chart.
- The root and canvas-bot service accounts can no longer be disabled, deleted, or renamed from the Django admin, preventing accidental lockouts that block Canvas Medical support access. Other users are unaffected.
- Plugin developers can now create, update, and mark lab reports as entered-in-error via the SDK, and attach lab results (tests and values) to an existing report. This supports workflows where a report is created first and its results arrive later, such as async OCR.
- Plugins can now redirect users to an internal Canvas page or an approved external URL after an action such as signing a note, opening the destination in the same tab or a new tab.
- The Refill Requests panel assignee filter is now multi-select — you can combine options like Me, staff on your care team, other staff, and specific prescribers. The IGNORE action now appears on all refill requests, not only suspected duplicates.
- Application menu items in the navigation sidebar now display a red notification badge with a count (capped at "99+") and a bolded label when an application has pending notifications.
