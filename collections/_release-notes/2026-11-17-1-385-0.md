Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Plugin pages and actions no longer stall and fail for about 20 seconds right after a Canvas update or when the instance adds capacity. A server now receives traffic only once its plugins are loaded.
- Fixed an issue where report-ready emails (Google Delivered reports and report jobs) did not link the report address, so it was not clickable in every mail client, including Outlook. The link is now clickable.
- Fixed an issue where the revamped note scrolled while saving. The revamped note now stays still while it saves.
- Fixed an issue where background jobs stalled after a worker restart. Each background worker process now uses its own database connection.
- Fixed an issue where a command being edited in the revamped note did not stay below the note header while the note scrolled. The command now stays below the note header.
- Fixed an issue where opening a prospect's EMR from Canvas Platform did not sign them in after Continue. It now signs them in on a page styled like Canvas Platform.

<span class="tag-sdk">sdk</span>

- Health Gorilla lab results now show abnormal flags that labs send under the standard HL7 interpretation code system (v2-0078). These flags were previously dropped, so some results that showed no flag before may now show H or L.
- Care protocols can now display a "Not relevant" status in the patient list, shown alongside the existing Due, Satisfied, Not applicable, and Pending states.
- FHIR Medication text search (`_text`) now matches regardless of unit spacing: `500mg` and `500 mg` return the same medications, including decimal strengths such as `0.5mg`. A glued strength can also return neighboring strengths (`5mg` includes `25 mg`).
- In the revamped note, [commands](/sdk/commands/) added by a plugin or the API show a sparkle after their title. Hover it to see where the command came from and who last edited it. In the standard note, commands added by a plugin or the API show a "Plugin Generated" or "API Generated" label on every instance.
- Improved performance and stability of provenance record lookups, which on instances with large amounts of history could previously cause heavy database load and slow the whole instance.
- Security fix: the real-time messaging and PDF generation services now run on a Node.js version patched against a remote code execution vulnerability (CVE-2026-111497).
- The messaging service uses an updated MessagePack library that fixes two denial-of-service vulnerabilities.
- The messaging WebSocket server verifies the TLS certificates of every connection it makes, including its database.
- Platform promotion now copies the settings and records Implementation configures on every instance from dev to prod. This covers on/off, number, text and choice settings, security settings that can only become stricter in prod, questionnaires and templates, letter templates, patient groups, fee schedules, discounts, payers, the referral directory, DME products, protocol settings, and allowlisted [organization](/api/organization/) and practice location settings. Values that a setting cannot hold, or that would loosen security, are refused instead of written.
- Fixed an issue where a newly added patient address, facility address, phone number, consent, or care team member occasionally stayed hidden on the patient profile until the page was reloaded. These now show up right away.
- Medication lookups by RxNorm code are faster.
