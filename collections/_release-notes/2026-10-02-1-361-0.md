Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Permalinks to notes now reliably open the target note expanded, including locked, signed, and booked or reverted appointment notes. Command permalinks now open on the Note tab even when the note type has a note application that opens by default, so the linked command is shown.

<span class="tag-sdk">sdk</span>

- Notes can now display their body grouped into clinical sections, with a new control to switch between the sectioned view and the whole note. Commands can also be dragged to reorder them within the note, and the new order is saved.
- Plugins can now add custom HTML content or embedded URLs to notes using [layout effects](/sdk/layout-effect/). The content can go inside the History, Exam, Assessment & Plan, or Internal sections, or at the top of the combined note view. This requires the note revamp to be enabled.
- Patients can download the after-visit summary of their own signed visits from the patient portal, as the same PDF a clinician prints from the note. Each download is recorded in the audit trail.
- Plugins can respond when a patient downloads a document from the portal with the new `PATIENT_PORTAL__DOCUMENT_DOWNLOADED` event. It targets the patient and carries the document type and note ID, so a plugin can link a patient to `/app/note/<note id>/aftervisitsummary` and record that they received it.
- Plugins can open a blocking modal: a [LaunchModalEffect](/sdk/layout-effect/#modals) with `dismissible=False` cannot be closed with Escape, a backdrop click, the back arrow, or navigation, and closes only when its own frame posts `CLOSE_MODAL`. Modals that do not set the field behave as before.
- No user-facing change. Draft pull requests no longer run the Cypress end-to-end suite until they are marked ready for review, which cuts CI cost.
