Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Fixed an issue where the patient chart's Goals "Active/Closed" filter classified goals incorrectly. The filter now classifies each goal by its most recent update, so a goal that was updated while active and later closed no longer appears under "Active" or sorts by an outdated due date.
- SDK data-module plugins can now access an imaging report's underlying file URL through the ImagingReport model's `document_url`, mirroring how DocumentReference already exposes its file.

<span class="tag-sdk">sdk</span>

- Running `canvas plugin validate` no longer reports library-owned handler classes in hidden directories (e.g. `.venv/`) as unreferenced, so plugin authors stop seeing spurious validation warnings.
- Plugins using the Canvas SDK can now read external care team members (e.g. an external PCP) and their contact info such as fax directly through the [CareTeamMembership](/sdk/data-careteammembership/) data module — via the new OrganizationalEntity data model and the `CareTeamMembership.organizational_entity` relationship — instead of a per-patient FHIR lookup.
- Plugin developers can now read Educational Material command data (title, article, selected/available languages, abstract, and related fields) through the SDK data module.
- Plugins can now control which items appear in the provider (hamburger) menu via a new [ProviderMenuConfiguration](/sdk/effect-provider-menu-configuration/) SDK effect. For example, a scheduling plugin can hide the native Schedule item so it no longer renders in the sidebar.
- Fixed an issue where updating or reinstalling a plugin could temporarily block a user's IP address with a site-wide "403 Forbidden" while the plugin reloaded.
