Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where the default supervising provider dropdown on a staff member in Settings listed the same provider once for every prescriber role they hold. Each provider now appears once.
- Fixed an issue where a note could keep showing its previous scheduling status until the page was reloaded. The status now updates as soon as a pending follow-up request is removed, or the Reschedule window is closed without booking.

<span class="tag-ui">ui</span>

This release includes 2 new commands to help manage a patient's conditions. Both sit in the note's History section, so they group under History when the note is printed or sorted into SOAP or APSO order.

- **Add Condition** records a previously diagnosed condition that is still active. [Read more](https://help.canvasmedical.com/articles/9221634314-new-diagnoses).
  - The condition goes on the Conditions list as active, and no assessment is opened for it.
  - Diagnose stays the command for an active condition you are assessing for the first time, and Past Medical History for backfilling one that is not active now.
  - It uses the same ICD-10 condition picker as Diagnose, and captures a background, an approximate date of onset, and comments.
  - An informational message appears when the condition is already on the patient's Conditions list.
- **Remove Past Medical History** removes a past medical history condition from the patient's chart and records the rationale why. [Read more](https://help.canvasmedical.com/articles/3935780129-managing-historical-conditions).
  - The note that originally recorded the entry is left as it is, so the chart still shows what was documented and when.
  - An entry that has an assessment is not offered for removal.
  - Entering the removal in error puts the entry back on the patient's chart.

<span class="tag-sdk">sdk</span>

- Fixed an issue where a plugin's [SimpleAPI](/sdk/handlers-simple-api-http/) endpoints briefly stopped responding while the plugin was being reinstalled or upgraded. The running version now keeps serving until the new one has loaded, and stays in place if the new version fails to load.
- Plugins can now originate, edit, commit, delete, and enter in error the [Add Condition](/sdk/commands/#addcondition) and [Remove Past Medical History](/sdk/commands/#remove-past-medical-history) commands, alongside the clinicians using them in the note.
  - Add Condition takes an `icd10_code`, and optionally a background, an approximate date of onset, and comments.
  - Remove Past Medical History takes the `condition_id` of a committed past medical history entry on that patient that carries no assessment, and an optional rationale.
  - Each command emits the full set of lifecycle events, along with the search events its condition picker fires. See [Add Condition](/sdk/events/#add-condition-command) and [Remove Past Medical History](/sdk/events/#remove-past-medical-history-command) in the events reference.
- The [RemovePastMedicalHistoryEvent](/sdk/data-remove-past-medical-history-event/) data module is now available, so plugins can read which past medical history entries were removed, on which note, and the rationale given for each.
  - The same records are reachable from the [Condition](/sdk/data-condition/) that was removed, and from the [Patient](/sdk/data-patient/#patient) or [Note](/sdk/data-note/) they were recorded on.
