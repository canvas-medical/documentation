Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Fixed an issue where the return address on the patient statement payment stub was not centered in the return envelope window, causing the organization name to be cut off. The return address now sits centered in the window.
- Order DME commands can now be linked to an Assess command in the same note, just like other orders. Drag an Order DME onto an Assess, or add it from inside one, and it nests under that Assess, fills its Indications with the Assess's ICD-10 codes, and prints under it. If the Assess is entered in error, the Order DME moves back to the top level. Plugins can set the link using `assessment_id`.
- Fixed an issue where v2 notes did not show commands that a plugin chart tab added while it was open until the page was refreshed. The new commands now appear right away.

<span class="tag-sdk">sdk</span>

- Plugins can now attach uploaded images to a patient's insurance coverages and identification cards. They can also create, update, expire, remove, and reorder coverages, add PNG, JPEG, or PDF attachments to messages, and add an image to [Visual Exam Finding](/sdk/commands/#visualexamfinding) commands.
- Hovering an application icon in the patient chart panel now shows the application's name in a tooltip. Application icons in the panel and the applications drawer also use the application's name as their alt text, so screen readers announce them correctly.
- Internal: reduced plugin metrics volume by dropping the redundant `plugins.executions` counter and the `container_index` tag on plugin metrics.
- [Assess](/sdk/commands/#assess) has a new "Show in problem list" checkbox. Turn it off to record a diagnosis for this visit only: it is assessed, appears in billing, and can be linked from Plan commands, but stays off the patient's problem list. Turning it back on in a later visit moves the condition onto the problem list. Developers: `AssessCommand` accepts `show_in_problem_list`.
- Internal: plugin effect failures are now counted correctly in the `plugins.effects_handled` metric.
- Security improvements across the patient portal and staff admin: stricter consent handling in the portal, safer spreadsheet exports and document rendering, tighter permission checks on CCDA and admin actions, and outbound document and SIEM requests now limited to public destinations.
- No user-facing change; this makes an end-to-end test reliable.
