Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Patients who open the portal at a URL without a trailing slash, such as `/app`, now reach the portal instead of seeing a 403 Forbidden.
- Fixed an issue where patient portal invite and password-reset links showed a false "Expired link" error when the patient already had an active session or reopened the link, preventing returning patients from finishing sign-up or password reset. When a link genuinely can't be used, the screen now names the real cause (e.g. a different account is signed in) and offers a one-click way to continue.
- Fixed an issue where patient portal invite and password-reset links failed on reload, link preview, or mail-scanner prefetch and showed "Expired link" on the first open. The link is now spent only when the password is actually set. When a different account (e.g. a staff member) holds the browser session, the page now offers a one-click "Sign out and continue" instead of a dead-end expired message.

<span class="tag-sdk">sdk</span>

- Vital sign readings are now accessible through the SDK data module. Plugins can read a patient's recorded vitals along with each individual measurement — sign, LOINC code, value, and units — reached via the reading's signs.
- The [Lab Order](/sdk/commands/#laborder) command's `comment` is now limited to 128 characters.
- The [Immunize](/sdk/commands/#immunize) command is now available in the SDK. [Vaccine](/sdk/data-vaccine/), [VaccineLot](/sdk/data-vaccine-lot/), and [VaccineManufacturer](/sdk/data-vaccine-manufacturer/) are available in the SDK data module.
