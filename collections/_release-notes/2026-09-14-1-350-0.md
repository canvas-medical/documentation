Today's release includes the following updates:

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where an unsaved change to a note's body stayed on screen after the save failed, until the page was reloaded. The note now reverts to its last saved state.
- Fixed an issue where a phone number entered with a leading US country code, such as `1-425-208-9647` or `+1 425-208-9647`, saved with its last digit dropped. It now saves as the correct 10-digit number.
- Fixed an issue where the Type filter in the revenue claims queue showed an empty dropdown, so claims could not be filtered by note type. It lists the available note types again.
- A condition with no diagnosis code now shows just its name in the chart summary. It previously carried an empty pair of parentheses after the name.

<span class="tag-ui">ui</span>

- In the patient chart Conditions summary, a condition without an ICD-10 code now offers a single [Change Diagnosis](/sdk/commands/#updatediagnosis) button, with that condition already selected, so a clinician can recode it to an ICD-10 diagnosis before assessing it. Conditions that carry an ICD-10 code keep Resolve and Assess, and past conditions keep Activate.
  - The Assess command's condition picker no longer offers conditions without an ICD-10 code, since Assess acts on that code.
- When linking a patient to a Data Integration document, the patient's date of birth now appears next to their name.

<span class="tag-sdk">sdk</span>

- Plugins can now read coding gap command events through the SDK data module, covering the create, validate, assess, and defer actions taken on a detected issue. [Read more](/sdk/data-coding-gap-event/).
- Plugins can now make chart phone numbers clickable for click to dial, using the [phone dial configuration effect](/sdk/effect-phone-dial-configuration/) to set whether numbers are clickable and whether a click opens the device dialer or is handled by the plugin.
  - This is set for each of the patient, patient contacts, and external care team sections. Fax numbers are never clickable.
  - A plugin receives an event when a number is clicked. Where no plugin responds, phone numbers stay plain text as they do today.
- The [Reference](/sdk/commands/#reference) command is now exposed through the SDK data module, so a plugin can read a reference's patient, note, linked diagnostic view, name, and content.
- Plugins can now read `Group` records through the SDK data module, including each group's external identifier and its link to the underlying team or patient group.

<span class="tag-config">config</span>

- A new `EXCLUDE_ENTERED_IN_ERROR_FROM_NOTE_DOCUMENTS` setting keeps commands marked entered in error out of the locked note that integrations read, both the FHIR DocumentReference PDF and the copy exposed through the SDK data module. The audit copy linked at the bottom of the note still shows them.
  - The setting is off by default and an admin can turn it on. It applies to notes locked from that point on, so reach out to Canvas support to have notes locked earlier brought in line.
