Today's release includes the following updates:

<span class="tag-ui">ui</span>

- Getting a form signed is now simpler! Lab, Imaging, Consult/Referral, and Uncategorized documents can now go to a teammate, a team, or a provider for signature, and each one keeps a full history of who did what. [Sending Documents for Signature](https://help.canvasmedical.com/articles/7724253029-sending-documents-for-signature) walks through each step and the permissions you need.
  - **Reassign** sends a document to a person, a team, or both, with an optional comment. On Uncategorized documents, it takes the place of Delegate.
  - **Send for signature:** mark where the provider signs and dates the form, then select **SEND FOR SIGNATURE**. The provider selects **SIGN FORM** to add their saved signature and today's date, and the form comes back to you.
  - **Add comment** leaves a comment on a document without changing who it's assigned to.
  - Each document's history shows its reassignments, comments, signatures, and reviews in one timeline.
  - The review's **SIGN** button is now **RECORD** in [Lab](https://help.canvasmedical.com/articles/1652834476-processing-lab-reports), [Imaging](https://help.canvasmedical.com/articles/7566748234-process-image-results), [Consult](https://help.canvasmedical.com/articles/8177085140-consult-report-review), and [Uncategorized](https://help.canvasmedical.com/articles/2240101532-command-uncategorized-document-review) reviews.

<span class="tag-sdk">sdk</span>

- Plugins can now manage a claim's assignee.
  - **Effect:** [assign a claim](/sdk/effect-claims/#assign) to a staff member or a team, or [clear its assignment](/sdk/effect-claims/#unassign).
  - **Event:** [react when a claim's assignment changes](/sdk/events/#claims).
  - **Data:** read [who a claim is assigned to](/sdk/data-claim/#claim), whether a staff member or a team.
- Plugins can now follow document hand-offs and signatures.
  - **Events:** [react when a document is reassigned or gets a comment](/sdk/events/#document-hand-off).
    - [DOCUMENT_DELEGATED](/sdk/events/#document-hand-off) now fires only when staff select **SEND FOR SIGNATURE**, and when the provider selects **SIGN FORM** and the signed form goes back. Its target is the report. Plugins that followed every hand-off with it should listen for DOCUMENT_REASSIGNED instead.
  - **Data:** read [each document's history](/sdk/data-document-history-event/), and the [signature requests](/sdk/data-document-review-delegation/) on [Lab](/sdk/data-labs/#delegations), [Imaging](/sdk/data-imaging/#delegations), and [Referral](/sdk/data-referral/#delegations) reports, as on Uncategorized documents.

<span class="tag-bugfix">bugfix</span>

- Fixed an issue where [calendar events a plugin created](/sdk/calendar-event-management-effects/) couldn't be updated or removed later, so a canceled or changed event stayed on the Canvas calendar. Canvas now keeps the `event_id` a plugin sends when it creates an event.
- Fixed an issue where a letter was locked when its PDF failed to generate during printing, so it couldn't be fixed or printed again. A letter now locks only once its PDF is generated, so you can remove a problem attachment and print again.
- Fixed an issue where entering a payment posting on a claim in error left that posting's allowed amounts active on the claim, so they still counted in allowed-amount reports and exports. The allowed amounts are now voided along with the posting.
- Fixed an issue where adding a command from the chart panel, such as Refill, Assess, or Stop, could replace the text typed on the line where the cursor sat. The command is now added below that line.
  - If a command can't be added, an error message appears, and a refill request's Approve and Deny buttons come back.
- Fixed an issue where a command or line added to a note could disappear from the note body when the note was checked in, locked, signed, or updated by a plugin at the same moment, or when a plugin added lines while a command was being added.
- Fixed an issue where a plugin's follow-up edit to a [Review of Systems](/sdk/commands/#review-of-systems) or [Physical Exam](/sdk/commands/#physicalexam) command, such as switching answered sections on, was undone after another plugin updated the command.
- Fixed an issue where updating a note through the [Note API](/api/note/) changed the note's originator. The user who created the note stays its originator.
