Today's release includes the following updates:
<span class="tag-bugfix">bugfix</span>

- Fixed an issue where diagnosis text and ICD-10 codes were no longer displayed in bold on note printouts in the Assessment section for the Assess, Diagnose, Change Diagnosis, Assess Coding Cap, and Resolve Condition commands.
- Fixed an issue where timeline letter and message content was sometimes not being saved.

<span class="tag-sdk">sdk</span>

- Fixed an issue where scheduling availability could lose calendar holds and staff shift data when a Google Calendar's event cache hadn't been refreshed in roughly a month. The cache now refreshes automatically instead of falling back to incomplete data.
- Refill denials now reliably send back to the pharmacy even when the original RefillRequest had a missing or zero quantity. Previously a denial in this case could fail validation and never be transmitted.
- Protocol card recommendation clicks now emit an analytics event tagged with protocol key, kind (sdk/workflowkit/hyperlink), plugin name, and command type, so built-in CQM clicks are measurable alongside SDK and hyperlink clicks.
- Prescriptions that the pharmacy has confirmed receiving no longer get stuck showing as pending; their status now reflects that the pharmacy accepted them.
- Pharmacy e-prescribing errors now surface a short, readable message instead of an opaque "Server Error (500)" HTML page when an unexpected failure occurs.
- Plugin developers can now read incoming refill requests — including their medication codings and the prescriptions that respond to them — through the Canvas SDK data module.
